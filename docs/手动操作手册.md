# WPS Office 开机自启彻底关闭 · 全手动操作手册

> **适用对象**：WPS Office 12.x，用户级安装（落在 `%LOCALAPPDATA%\Kingsoft\WPS Office`）
> **执行环境**：Windows 10 / Windows 11，CMD 与 PowerShell 5.1 及以上
> **手册性质**：纯手动。每条命令都给出「做什么 / 预期输出 / 失败怎么办」，可逐条照抄。
> **本机实测基线**：用户 `DESKTOP-ASACLVM\YEHY`，版本目录 `C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690`，WPS 12.1.0.29690。
> **改动范围**：仅 `%LOCALAPPDATA%\Kingsoft\` 下的计划任务、服务、文件 ACL 与一个启动器可执行文件；不动主程序、不动文档、不动用户配置。

## 0 五分钟速查表（最关键 6 条命令）

> 只想要结果的人：按这 6 条走完，闸1～闸4 就都上了（闸5 升级通道见第 12 章，可选）。每一步的细节、判据、回退在后续章节。
> 约定：`<VER>` = 版本目录（如 `12.1.0.29690`），`<USER_FQ>` = `%USERDOMAIN%\%USERNAME%`（如 `DESKTOP-ASACLVM\YEHY`）。

### 速查 1｜锁定安装根与版本目录（PowerShell，先跑这一条）

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"; $Ver = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName; "$Root`n$Ver"; Test-Path "$Ver\office6\wpsoffice.exe","$Ver\wtoolex\wpsupdate.exe","$Root\ksolaunch.exe","$Ver\office6\ksolaunch.exe"
```

### 速查 2｜备份两条计划任务为 XML（普通权限即可）

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"; New-Item -ItemType Directory -Force $B | Out-Null; $U = "$env:USERNAME"; Export-ScheduledTask -TaskName "WpsUpdateTask_$U" -TaskPath "\" | Set-Content "$B\WpsUpdateTask_$U.xml" -Encoding UTF8; Export-ScheduledTask -TaskName "WpsUpdateLogonTask_$U" -TaskPath "\" | Set-Content "$B\WpsUpdateLogonTask_$U.xml" -Encoding UTF8; Get-ChildItem $B
```

### 速查 3｜备份 5 个载荷的原件哈希（后面要逐项比对）

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"; $Ver = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName; $f = @("$Root\ksolaunch.exe","$Ver\office6\ksolaunch.exe","$Ver\wtoolex\wpsupdate.exe","$Ver\wtoolex\updateself.exe","$Ver\wtoolex\updatepolicy.exe"); $f | Where-Object { Test-Path $_ } | ForEach-Object { $h = (Get-FileHash $_ -Algorithm SHA256).Hash; "{0}  {1}" -f $h, $_ }
```

### 速查 4｜禁用并删除两条自启计划任务（管理员 CMD）

```cmd
schtasks /Change /TN "WpsUpdateTask_%USERNAME%" /DISABLE
schtasks /Change /TN "WpsUpdateLogonTask_%USERNAME%" /DISABLE
schtasks /Delete /TN "WpsUpdateTask_%USERNAME%" /F
schtasks /Delete /TN "WpsUpdateLogonTask_%USERNAME%" /F
```

### 速查 5｜锁死 4 个更新/自启载荷（管理员 PowerShell，自动探测版本目录）

> 不要用 CMD 写 `%LOCALAPPDATA%\...\%VER%\...` —— CMD 里没有 `%VER%` 这个变量，会展开成空字符串，路径变成 `...\WPS Office\\office6\...`，命令静默失败还不报错。用下面这段自探测的 PowerShell。

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName
$U    = "$env:USERDOMAIN\$env:USERNAME"

# 禁执行 + 禁改 + 禁删：4 个更新/自启载荷
$Exec = @(
    "$Ver\office6\ksolaunch.exe",
    "$Ver\wtoolex\wpsupdate.exe",
    "$Ver\wtoolex\updateself.exe",
    "$Ver\wtoolex\updatepolicy.exe"
) | Where-Object { Test-Path $_ }

foreach ($f in $Exec) {
    icacls "$f" /deny "${U}:(X,WD,AD,WEA,WA,DE)"
}

# 目录禁新建子项：挡住"升级后铺新版本目录"
icacls "$Root" /deny "${U}:(WD,AD)"

# 复核
foreach ($f in $Exec) {
    "{0,-22} {1}" -f (Split-Path $f -Leaf), $(if ((icacls "$f" 2>&1 | Out-String) -match 'DENY') { 'DENY 在位' } else { '未生效' })
}
"{0,-22} {1}" -f 'WPS Office', $(if ((icacls "$Root" 2>&1 | Out-String) -match 'DENY') { 'DENY 在位' } else { '未生效' })
```

> 注意 `"${U}:(X,WD,AD,WEA,WA,DE)"` 里的 `${U}` 大括号不可省。PowerShell 会把 `$U:` 当成驱动器限定符而报语法错，这是踩过的坑。

### 速查 6｜服务禁用 + 总校验（管理员）

```cmd
sc.exe config wpscloudsvr start= disabled
sc.exe stop wpscloudsvr
```

```powershell
& "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.exe" /wpsupdate -from=task -source=task; Start-Sleep 5; "剩余进程: " + (Get-Process wps,wpsoffice,wpscloudsvr -ErrorAction SilentlyContinue).Count
```

> 判据：最后一条输出 `剩余进程: 0`。图标双击应能正常开 WPS。

## 1 原理与为什么普通办法无效

### 1.1 WPS 12.x 的自启动是三层结构

WPS Office 12.x 的自启不靠单点，而是三层互相兜底。任何一层漏掉，另一层就会把它补回来。

**第一层：两条计划任务（每次开机/每小时都会触发）**

| 任务名 | 触发时机 | 动作 |
|---|---|---|
| `\WpsUpdateTask_<用户名>` | 每小时一次 | `%LOCALAPPDATA%\Kingsoft\WPS Office\ksolaunch.exe /wpsupdate -from=task -source=task` |
| `\WpsUpdateLogonTask_<用户名>` | 用户登录后延迟 29 分钟 | `%LOCALAPPDATA%\Kingsoft\WPS Office\ksolaunch.exe /wpsupdate -from=task -source=task` |

两条任务的**动作完全相同**，都指向安装根目录下的 `ksolaunch.exe`。这就是为什么闸4（换壳）能一次掐掉两条任务的入口：任务本身哪怕还在，动作对象已经变成「只放行正常启动」的守卫壳。

**第二层：自我重建（把删掉的任务补回来）**

`<版本目录>\wtoolex\wpsupdate.exe` 支持两条自我修复指令：

- `-createtask`：重新创建计划任务
- `-repairtask`：检查并修复计划任务

实测日志原文（更新器自己打的，不是推测）：

```text
kupdate::Execute cmd=[-createtask]
kupdate::Execute cmd=[-repairtask]
run repair schd exec success
```

`run repair schd exec success` 这句是关键：它表示「计划任务修复流程执行成功」。也就是说，你在任务计划程序里手工删掉的任务，只要 `wpsupdate.exe` 还能跑起来，下一次更新检查就会把它重新注册回来。**这就是「删了任务过几天又冒出来」的根因。**

**第三层：安装器装完自启（重装/升级时触发）**

安装器完成后调用：

```text
wps.exe /prometheus /from=autostart_after_install
```

这条与计划任务无关，是安装流程最后一步直接把 WPS 拉起来。所以「重装 WPS 之后自启又回来了」是设计行为，不是玄学。

### 1.2 关键事实：WPS 不在 Run 注册表里

这是整件事的分水岭。查一遍就清楚：

```powershell
"--- HKCU Run ---"; Get-ItemProperty 'HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run' -ErrorAction SilentlyContinue | Format-List
"--- HKLM Run ---"; Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run' -ErrorAction SilentlyContinue | Format-List
```

**做什么**：列出两个 Run 键的全部值，确认里面有没有 WPS / Kingsoft 相关项。
**预期输出**：常见的只有微信、输入法、显卡驱动之类；**WPS 相关项不出现**。
**失败怎么办**：所谓「失败」在这里指「居然出现了 WPS 项」。那就顺手把它备份下来再删：

```cmd
reg export "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" "%USERPROFILE%\Desktop\wps-backup\run.reg" /y
reg delete "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" /v WPS /f
```

于是问题来了：**任务管理器「启动」选项卡、各类安全软件的「启动项管理」，本质上读的都是 Run 键和 Startup 文件夹**。WPS 既然不在这两处，这些工具自然一条都扫不到，界面上干干净净，开机照样起来。

| 你用的办法 | 为什么对它无效 |
|---|---|
| 任务管理器 → 启动 → 禁用 | WPS 不在 Run 键 / Startup 文件夹，列表里根本没有它 |
| 安全软件「启动项清理」 | 同上，扫的是 Run 键与 Startup 目录 |
| 卸载「WPS 云服务」 | 计划任务与 `ksolaunch.exe` 仍在，照旧触发 |
| 组策略禁止「WPS 更新」 | 只作用于更新流程，第二层会用 `-repairtask` 重建 |
| 手工删计划任务（不做闸3/闸4） | 第二层 `wpsupdate.exe -createtask` 会把它重建回来 |
| 直接删 `ksolaunch.exe` | 主图标与两条任务共用这个文件，删了图标一起废；且更新器会补文件 |

### 1.3 五道闸总览

| 闸 | 目标 | 手段 | 权限 | 是否可缺 |
|---|---|---|---|---|
| 闸1 | 那两条计划任务 | `schtasks /Change /DISABLE` + `/Delete` | 管理员（DACL 受限时必需） | 可缺，但漏了会残留触发 |
| 闸2 | `wpscloudsvr` 服务 | `sc.exe config ... start= disabled` + `sc.exe stop` | 管理员 | 可缺，云文档相关功能会拉进程 |
| 闸3 | 更新与自启的**载荷**（4 个 exe） | `icacls /deny` 精确权限位 | 本人账户即可（用户级安装） | **核心，缺了整件事会回弹** |
| 闸4 | 根目录 `ksolaunch.exe` 这个共用入口 | 换成自编译守卫壳 | 本人账户即可 | **保住图标必需** |
| 闸5 | 升级检测的三处服务器地址 | 注册表 `UpdateSvr` / `UpdateSecSvr` / `NotifySvr` → `127.0.0.1:9` | 本人账户即可 | 可选，与闸3 互补：闸3 让它跑不起来，闸5 让它跑也拿不到版本 |

**五道闸的分工一句话**：闸3 让「更新的手」动不了，闸4 让「自启的嘴」说不上话，闸1/闸2 把已经存在的地基拆掉，闸5 把「升级的路」指到本机黑洞。闸3+闸4 是主承重，闸1+闸2 是清场，闸5 是通道级兜底——闸3 因升级换了新文件而失效时，坏掉的值仍然是坏的。

## 2 手工准备：确认安装布局

> 目标：在动手前拿到三样东西 —— 安装根目录、版本目录、以及 4 个载荷文件的真实存在性。布局搞错，后面全部命令都会打在空气上。

### 2.1 一条脚本摸清全部路径（推荐先跑这个）

```powershell
$Root = Join-Path $env:LOCALAPPDATA 'Kingsoft\WPS Office'
if (-not (Test-Path $Root)) { "安装根不存在：$Root" }
$VerDir = Get-ChildItem $Root -Directory -ErrorAction SilentlyContinue |
          Where-Object { $_.Name -match '^\d+(\.\d+)+$' } |
          Sort-Object { [version]$_.Name } -Descending | Select-Object -First 1
"安装根   : $Root"
"版本目录 : $($VerDir.FullName)"
$probe = @(
    (Join-Path $Root 'ksolaunch.exe'),
    (Join-Path $Root 'ksolaunch.real.exe'),
    (Join-Path $VerDir.FullName 'office6\ksolaunch.exe'),
    (Join-Path $VerDir.FullName 'office6\wpsoffice.exe'),
    (Join-Path $VerDir.FullName 'office6\wps.exe'),
    (Join-Path $VerDir.FullName 'wtoolex\wpsupdate.exe'),
    (Join-Path $VerDir.FullName 'wtoolex\updateself.exe'),
    (Join-Path $VerDir.FullName 'wtoolex\updatepolicy.exe')
)
$probe | ForEach-Object { "{0,-6} {1}" -f $(if (Test-Path $_) { 'OK' } else { 'MISS' }), $_ }
```

**做什么**：自动挑出编号最大的版本目录，然后逐个探测 8 个关键文件是否存在。
**预期输出**（本机实测）：

```text
安装根   : C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office
版本目录 : C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690
OK     C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\ksolaunch.exe
OK     C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\ksolaunch.real.exe
OK     C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\office6\ksolaunch.exe
OK     C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\office6\wpsoffice.exe
OK     C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\office6\wps.exe
OK     C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\wtoolex\wpsupdate.exe
OK     C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\wtoolex\updateself.exe
OK     C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\wtoolex\updatepolicy.exe
```

**读法**：`office6` 目录下同时存在 `ksolaunch.exe`、`wpsoffice.exe`、`wps.exe` 三个可执行文件（本机实测，三者都是 1.2～1.3 MB），所以三条都是 `OK`。
`ksolaunch.real.exe` 这一行本身就是「壳是否已落位」的天然标记，**比看体积可靠**：尚未替换守卫壳时为 `MISS`，替换完成、原版改名存档后变成 `OK`。上面这份输出是「已落位」状态（本机当前就是这种），所以是 `OK`。

**失败怎么办**：
- `安装根不存在` → 走 2.2～2.4 的注册表/兜底探测，确认是全局安装（`Program Files`）还是根本没装。
- `wtoolex` 整目录 MISS → 该版本不带独立更新器，闸3 只锁 `office6\ksolaunch.exe`，闸4 照做，见第 11 章。
- 根 `ksolaunch.exe` MISS → 该版本没有根级启动器，图标直接指向版本目录，闸4 整章跳过，只做闸1/2/3。

### 2.2 来源一：注册表 InstallRoot（三处都要查）

```cmd
reg query "HKLM\SOFTWARE\Kingsoft\Office\6.0\common\InstallRoot" /v InstallRoot
reg query "HKLM\SOFTWARE\WOW6432Node\Kingsoft\Office\6.0\common\InstallRoot" /v InstallRoot
reg query "HKCU\SOFTWARE\Kingsoft\Office\6.0\Common\InstallRoot" /v InstallRoot
```

**做什么**：分别问 64 位 HKLM、32 位视图 HKLM、当前用户 HKCU 三个位置「WPS 装在哪」。
**预期输出**（用户级安装通常只有 HKCU 有值）：

```text
HKEY_CURRENT_USER\SOFTWARE\Kingsoft\Office\6.0\Common\InstallRoot
    InstallRoot    REG_SZ    C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\
```

**失败怎么办**：
- 报 `系统找不到指定的注册表项或值` → 该处没有记录，换下一处，三处都空就走 2.3。
- 返回的是 `C:\Program Files\Kingsoft\...` → 属于全局安装，后续所有 ACL 与服务命令**必须用管理员 PowerShell**执行，见第 11 章。

### 2.3 来源二：App Paths 兜底

```cmd
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\wps.exe" /ve
reg query "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\wps.exe" /ve
```

**做什么**：App Paths 是 Windows 记录「某个 exe 装在哪」的标准位置，WPS 注册了就能直接读到主程序全路径。
**预期输出**：

```text
    (默认)    REG_SZ    C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\office6\wpsoffice.exe
```

拿到主程序路径后，**往上退两级**就是版本目录，再退一级就是安装根。

**失败怎么办**：两处都空 → 走 2.4 直接扫盘。

### 2.4 来源三：目录扫描兜底（最后手段）

```powershell
$cands = @(
    (Join-Path $env:LOCALAPPDATA 'Kingsoft'),
    (Join-Path ${env:ProgramFiles} 'Kingsoft'),
    (Join-Path ${env:ProgramFiles(x86)} 'Kingsoft')
) | Where-Object { Test-Path $_ }
foreach ($c in $cands) {
    "=== $c ==="
    Get-ChildItem $c -Directory -ErrorAction SilentlyContinue | ForEach-Object { "  " + $_.FullName }
    Get-ChildItem $c -Recurse -Depth 2 -Filter 'ksolaunch.exe' -ErrorAction SilentlyContinue |
        ForEach-Object { "  [launcher] " + $_.FullName }
}
```

**做什么**：在三个常见根下枚举子目录，并递归两层找 `ksolaunch.exe`。
**预期输出**（本机实测）：

```text
=== C:\Users\YEHY\AppData\Local\Kingsoft ===
  C:\Users\YEHY\AppData\Local\Kingsoft\WPS Cloud Files
  C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office
  [launcher] C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\ksolaunch.exe
```

**失败怎么办**：一个 `[launcher]` 都没有 → 这台机器上 WPS 是「绿色版/便携版」形态，启动方式由使用者自己决定，本手册第 1～9 章的前提不成立；直接跳到第 11 章确认适用范围。

### 2.5 权限自检（决定后面哪些命令要开管理员）

```powershell
$id = [Security.Principal.WindowsIdentity]::GetCurrent()
$isAdmin = ([Security.Principal.WindowsPrincipal]$id).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)
"当前账户 : $($id.Name)"
"管理员   : $isAdmin"
"安装根   : $env:LOCALAPPDATA\Kingsoft\WPS Office"
```

**做什么**：打印当前账户全名与是否管理员。
**预期输出**：`管理员 : False`（普通用户级操作即可完成闸3/闸4）。
**失败怎么办**：闸1、闸2 需要 `True`。**必须以管理员身份开一个新窗口**，不要在同一窗口里尝试提权：

```powershell
Start-Process powershell -Verb RunAs -ArgumentList '-NoExit','-Command','cd "$env:LOCALAPPDATA"'
```

## 3 备份清单（逐项写全）

> **这一章是整本手册的保险绳。** 做完这里的 6 类备份，第 9 章的「完全回退」才有意义。
> 备份原则：**原件 + 哈希 + 状态**三件套；原件用于回退，哈希用于证明回退干净，状态用于核对行为一致。

### 3.1 备份目录结构（先建好）

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"
New-Item -ItemType Directory -Force -Path $B, "$B\files", "$B\tasks", "$B\acl", "$B\reg" | Out-Null
Get-ChildItem $B | Select-Object Name, Mode
```

**做什么**：一次性建出 5 个子目录，后续备份各归各位。
**预期输出**：

```text
acl  files  reg  tasks
```

**失败怎么办**：桌面被重定向到别的盘（OneDrive 常见）时，改用固定路径 `New-Item -ItemType Directory -Force C:\wps-backup`，并把后面所有 `$B` 换成该路径。

**为什么备份要避开 `%LOCALAPPDATA%\Kingsoft`**：那个目录在闸3 里会被 `/deny (WD,AD)` 锁住，锁上之后往里面写备份文件会被权限拦住。备份一律放桌面或 `C:\wps-backup`。

### 3.2 备份一：两条计划任务的 XML（两种方法，都做）

**方法 A：Export-ScheduledTask（推荐，结构化最完整）**

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"; $U = $env:USERNAME
foreach ($n in @("WpsUpdateTask_$U", "WpsUpdateLogonTask_$U")) {
    try {
        Export-ScheduledTask -TaskName $n -TaskPath "\" |
            Set-Content -Path "$B\tasks\$n.xml" -Encoding UTF8
        "已导出: $n  ($((Get-Item "$B\tasks\$n.xml").Length) bytes)"
    } catch {
        "导出失败: $n  ->  $($_.Exception.Message)"
    }
}
Get-ChildItem "$B\tasks" | Select-Object Name, Length
```

**做什么**：把两条任务导成完整 XML（含触发器、动作、主体、设置）。
**预期输出**：

```text
已导出: WpsUpdateTask_YEHY  (3214 bytes)
已导出: WpsUpdateLogonTask_YEHY  (3307 bytes)
```

**失败怎么办**：
- `Access is denied` → 该任务 DACL 只给读权限之外的东西，先把任务本身读出来看一眼，再改用方法 B，或直接用管理员窗口重跑。
- 任务名对不上 → 先枚举真实任务名（见 6.1），把名字抄准。

**方法 B：schtasks /query /xml（CMD 版，用于交叉验证）**

```cmd
schtasks /query /tn "WpsUpdateTask_%USERNAME%" /xml > "%USERPROFILE%\Desktop\wps-backup\tasks\WpsUpdateTask_schtasks.xml"
schtasks /query /tn "WpsUpdateLogonTask_%USERNAME%" /xml > "%USERPROFILE%\Desktop\wps-backup\tasks\WpsUpdateLogonTask_schtasks.xml"
```

**做什么**：用 schtasks 再导一份，与方法 A 互为对照。
**预期输出**：两条命令都无报错，生成两个 xml 文件，内容以 `<?xml version="1.0" encoding="UTF-16"?>` 开头。

```text
SUCCESS: The parameters of scheduled task "WpsUpdateTask_YEHY" have been listed.
```

**失败怎么办**：`ERROR: The system cannot find the file specified.` → 任务已被删（或从没建过），记下这一点，第 9 章重建时跳过该条即可；把报错原文写进 `$B\tasks\_missing.txt` 留痕。

**为什么两种都要**：方法 A 的 XML 可直接喂给 `Register-ScheduledTask -Xml`；方法 B 是纯文本落盘，编码问题更少，回退时当参照。

### 3.3 备份二：5 个载荷文件的原件 + SHA256

要备份的 5 个文件（这份清单是全部，不多不少）：

| # | 文件 | 角色 | 换壳后是否还在原位 |
|---|---|---|---|
| 1 | `<安装根>\ksolaunch.exe` | 根级启动器（图标与两条任务共用） | 被替换为守卫壳；原版改名 `ksolaunch.real.exe` |
| 2 | `<版本目录>\office6\ksolaunch.exe` | 版本内启动器（更新器调用入口） | 保持原位，被 ACL 锁成不可执行 |
| 3 | `<版本目录>\wtoolex\wpsupdate.exe` | 更新器主体（`-createtask`/`-repairtask` 的执行者） | 保持原位，锁成不可执行 |
| 4 | `<版本目录>\wtoolex\updateself.exe` | 自我更新器（注意正确拼写是 **updateself.exe**，常被误写成 `upsdateself.exe`） | 保持原位，锁成不可执行 |
| 5 | `<版本目录>\wtoolex\updatepolicy.exe` | 更新策略器 | 保持原位，锁成不可执行 |

**备份命令（复制原件 + 计算哈希，一条脚本全做）**

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' |
         Sort-Object { [version]$_.Name } -Descending)[0].FullName
$items = @(
    @{ N='root-ksolaunch.exe';            P="$Root\ksolaunch.exe" },
    @{ N='office6-ksolaunch.exe';         P="$Ver\office6\ksolaunch.exe" },
    @{ N='wtoolex-wpsupdate.exe';         P="$Ver\wtoolex\wpsupdate.exe" },
    @{ N='wtoolex-updateself.exe';        P="$Ver\wtoolex\updateself.exe" },
    @{ N='wtoolex-updatepolicy.exe';      P="$Ver\wtoolex\updatepolicy.exe" }
)
$rows = foreach ($i in $items) {
    if (-not (Test-Path $i.P)) { [pscustomobject]@{ File=$i.N; Exists=$false; SHA256='(missing)'; Bytes=0; Path=$i.P }; continue }
    Copy-Item $i.P -Destination "$B\files\$($i.N)" -Force
    $h = (Get-FileHash $i.P -Algorithm SHA256).Hash
    [pscustomobject]@{ File=$i.N; Exists=$true; SHA256=$h; Bytes=(Get-Item $i.P).Length; Path=$i.P }
}
$rows | Format-Table -AutoSize
$rows | ConvertTo-Json -Depth 3 | Set-Content "$B\files\hashes-original.json" -Encoding UTF8
"哈希清单已落盘: $B\files\hashes-original.json"
```

**做什么**：把 5 个原件拷进 `files\`，同时算 SHA256，最后把整张表存成 JSON。
**预期输出**（本机实测，示例值；换机器/换版本会不同，以你自己跑出来的为准）：

```text
File                     Exists SHA256                                                           Bytes
----                     ------ ------                                                           -----
root-ksolaunch.exe         True 6A1E302155B25504DA98A6C9F0A67D837AFD850EDCD7729122B27C4DDB0D1557   …
office6-ksolaunch.exe      True 6A1E302155B25504DA98A6C9F0A67D837AFD850EDCD7729122B27C4DDB0D1557   …
wtoolex-wpsupdate.exe      True 9F2C…                                                             …
wtoolex-updateself.exe     True 3B71…                                                             …
wtoolex-updatepolicy.exe   True C40A…                                                             …
哈希清单已落盘: C:\Users\YEHY\Desktop\wps-backup\files\hashes-original.json
```

**失败怎么办**：
- 某个文件 `Exists=False` → 该版本没有这个组件，把 JSON 里对应行的 `SHA256` 记作 `(missing)`，第 5、9 章遇到它就跳过。**不要把缺失文件当成错误处理**。
- `Get-FileHash` 报文件被占用 → WPS 正在跑。先结束进程（第 8 章有命令），再重跑本段。
- 哈希表只留了内存没落盘 → 重跑最后两行，`ConvertTo-Json` 那步是必须的。

**为什么要哈希**：第 9 章回退后要证明「和动手前完全一样」。没有原始哈希，回退是否干净只能靠肉眼。

**做什么**：导出整个 Kingsoft 用户配置树（含 WPS 的 `coldStartup` 自启痕迹、激活信息、界面设置），以及 Run 键现状。

### 3.6 备份五：ACL 现状

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' |
         Sort-Object { [version]$_.Name } -Descending)[0].FullName
$targets = @(
    $Root,

    "$Ver\wtoolex\updatepolicy.exe"

foreach ($t in $targets) {
    $safe = ($t -replace '[\\:]', '_')
```

**做什么**：把 6 个目标对象（安装根 + 5 个文件）的完整 ACL 逐份存盘，文件名做了路径转义，便于回溯。
**预期输出**：6 个 `acl-before-*.txt`，每个几百字节到 1KB。

### 3.7 备份完整性校验（做完必须跑）

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"
$orig = Get-Content "$B\files\hashes-original.json" -Raw | ConvertFrom-Json
$bad = 0
foreach ($r in $orig) {
    if (-not $r.Exists) { "跳过（原件本来就不存在）: $($r.File)"; continue }
    $bak = "$B\files\$($r.File)"
    if (-not (Test-Path $bak)) { "缺备份文件: $($r.File)"; $bad++; continue }
    $h = (Get-FileHash $bak -Algorithm SHA256).Hash
    if ($h -eq $r.SHA256) { "OK   $($r.File)  $($h.Substring(0,16))…" }
    else { "MISMATCH $($r.File)`n  备份: $h`n  原始: $($r.SHA256)"; $bad++ }
}
"---"
"校验不通过项: $bad"
```

**做什么**：把备份出来的副本重新算一遍 SHA256，与原值逐个比对。
**预期输出**：

```text
OK   root-ksolaunch.exe  6A1E302155B25504…
OK   office6-ksolaunch.exe  6A1E302155B25504…
OK   wtoolex-wpsupdate.exe  9F2C…
OK   wtoolex-updateself.exe  3B71…
OK   wtoolex-updatepolicy.exe  C40A…
---
校验不通过项: 0
```

**失败怎么办**：出现 `MISMATCH` → 复制过程中断了，重新跑 3.3 的复制段落；连续两次不一致就换备份位置（可能是磁盘写入问题）。**校验不通过就不要往下做任何闸门操作。**

### 3.9 备份六：升级服务器地址（打算做闸5 就必做）

> 前三项是自启侧（闸1～闸4）的备份。这一项是**升级侧（闸5）专属**的备份，做不做取决于你打不打算执行第 12 章。
> 只要打算改 `UpdateSvr` / `UpdateSecSvr` / `NotifySvr`，这三条原值**必须在动手前存下来**——它们是分号分隔的多地址串，抄漏一段就恢复不回原样。
>
> **⚠ 只能用一次**：下面这条命令写的是固定文件名，**重复执行会覆盖上一次的备份**。在已经改过值的状态下重跑，会把 `127.0.0.1:9` 当成"原值"存下来，原始地址就找不回了。要重做请先把旧文件改名带时间戳。

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"
New-Item -ItemType Directory -Force "$B\reg" | Out-Null
$K = 'HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common'
$key = Get-Item $K

$up = foreach ($n in 'UpdateSvr','UpdateSecSvr','NotifySvr') {
    $v = Get-ItemPropertyValue -Path $K -Name $n -ErrorAction SilentlyContinue
    if ($null -eq $v) { [pscustomobject]@{ Name = $n; Exists = $false; Kind = ''; Value = '' } }
    else { [pscustomobject]@{ Name = $n; Exists = $true; Kind = $key.GetValueKind($n).ToString(); Value = $v } }
}
$up | Format-List
$up | ConvertTo-Json -Depth 3 | Set-Content "$B\reg\wps-update-svr-original.json" -Encoding UTF8
"已保存: $B\reg\wps-update-svr-original.json"
```

**做什么**：把三个升级服务器地址连同**值类型（Kind）**与存在性一起存成 JSON。
**预期输出**：

```text
Name        : UpdateSvr
Exists      : True
Kind        : String
Value       : http://update.wps.cn/updateserver/update;http://update2.wps.cn/updateserver/update

Name        : UpdateSecSvr
Exists      : True
Kind        : String
Value       : https://update.wps.cn/updateserver/update;https://update2.wps.cn/updateserver/update

Name        : NotifySvr
Exists      : True
Kind        : String
Value       : http://notify.wps.cn/notifyserver/notify

已保存: C:\Users\YEHY\Desktop\wps-backup\reg\wps-update-svr-original.json
```

**与 3.4 的关系**：3.4 导出的 `HKCU\SOFTWARE\Kingsoft` 整键里**本来就包含**这三个值，所以就算漏了这一节，`reg import` 也能兜底。但整键导出有 11～12 MB，恢复时是"整键覆盖"，会把你改过的其它 Kingsoft 设置一并冲掉；这一份 JSON 是**精准恢复**用的，只写这三个值。

**校验**：确认分号多地址没被截断。

```powershell
$o = Get-Content "$env:USERPROFILE\Desktop\wps-backup\reg\wps-update-svr-original.json" -Raw | ConvertFrom-Json
"UpdateSvr 地址条数: " + (@((($o | Where-Object Name -eq 'UpdateSvr').Value) -split ';')).Count + "（正常应为 2）"
```

**失败怎么办**：条数是 1 → 备份被截断，重做本节；全部 `Exists : False` → 该版本没有这些值名，照实记录即可，第 12 章会自动跳过不存在的值。

## 4 闸4 手工替换守卫壳（保住图标可用）

### 4.1 先讲清为什么必须换壳，而不是直接禁执行

WPS 主图标、开始菜单项、任务栏项、以及那两条计划任务，**共用同一个文件**：

```text
%LOCALAPPDATA%\Kingsoft\WPS Office\ksolaunch.exe
```

本机实测：双击桌面图标时，系统实际执行的命令行是

```text
C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\ksolaunch.exe /prometheus /fromksolaunch /from=startmenu
```

也就是说，如果对这个 exe 下 `(X,…)` 禁执行，**两条自启确实死了，但图标也一起死了** —— 用户点图标毫无反应。这就是很多「一键关闭 WPS 自启」脚本把 WPS 弄成废铁的原因。

正确做法：**把这个共用入口换成一个我们自己写的、能分辨来意的壳**：

| 来意 | 参数特征 | 壳的行为 |
|---|---|---|
| 计划任务触发 | `/wpsupdate -from=task -source=task` | 静默退出，退出码 0 |
| 更新器重建任务 | `-createtask` / `-repairtask` | 静默退出，退出码 0 |
| 安装器装完自启 | `/prometheus /from=autostart_after_install` | 静默退出，退出码 0 |
| 桌面 / 开始菜单 / 任务栏 | `/prometheus /fromksolaunch /from=startmenu` / `from=taskbar` | 转发到 `office6\wpsoffice.exe`，正常开 WPS |

### 4.2 铁律：参数判定必须逐 token 精确比对

**绝对不要用「整串子串包含」去判断参数。** 这不是洁癖，是两次实打实的事故：

| 事故 | 当时的写法 | 现象 | 根因 |
|---|---|---|---|
| 一 | 拦截词里含 `/prometheus` | 点图标毫无反应，WPS 像没装 | `/prometheus` 是 WPS **正常启动**标志，被当成自启拦掉了 |
| 二 | 用 `from=task` 做子串匹配 | 任务栏图标失灵 | `from=taskbar` **包含** `from=task`，正常入口被连坐 |

正确做法（本手册源码就是这么写的）：**按空白切分参数 → 每个 token 去掉前导 `-` 或 `/` → 转小写 → 与黑名单做 `==` 全等比较**。唯一允许 `Contains` 的地方是 `autostart`（因为它是 `from=autostart_after_install` 这个 token 内部的片段，且不会被任何正常入口包含）。

### 4.3 准备工作目录（不要在 WPS 目录里编译）

```powershell
$W = "$env:USERPROFILE\Desktop\wps-guard-build"
New-Item -ItemType Directory -Force -Path $W, "$W\src" | Out-Null
"工作目录: $W"
```

**做什么**：建一个干净的编译工作目录，编译产物先落在这里，最后一步才复制进 WPS 目录。
**预期输出**：`工作目录: C:\Users\YEHY\Desktop\wps-guard-build`
**失败怎么办**：桌面路径被重定向时改用 `$W = "C:\wps-guard-build"`，后续命令同步替换。

### 4.4 从原版 exe 提取图标，生成多尺寸 ICO（完整 PowerShell）

> 为什么必须做这一步：`csc` 编出来的 exe 默认没有图标，快捷方式、任务栏、Alt-Tab 会全部显示成「默认程序图标」。必须用 `/win32icon:` 把 WPS 官方图标编进去。
> 为什么用 `PrivateExtractIcons`：`ExtractAssociatedIcon` 只能拿到一张模糊的 32×32；`PrivateExtractIcons` 能按尺寸精确取 16/32/48/256，再手工拼成标准 ICO。

把下面整段保存为 `$W\Extract-WpsIcon.ps1` 再执行，或直接整段贴进 PowerShell 窗口。

```powershell
#requires -Version 5.1
# Extract-WpsIcon.ps1 —— 从原版 exe 提取图标，生成 16/32/48/256 四尺寸 wps.ico
param([string]$RealExe)

$ErrorActionPreference = 'Stop'
$W = "$env:USERPROFILE\Desktop\wps-guard-build"
New-Item -ItemType Directory -Force -Path "$W\src" | Out-Null
$IcoPath = Join-Path "$W\src" 'wps.ico'

if (-not $RealExe) { $RealExe = Join-Path $env:LOCALAPPDATA 'Kingsoft\WPS Office\ksolaunch.exe' }
if (-not (Test-Path $RealExe)) { throw "找不到源 exe：$RealExe" }
Write-Host ("源文件: " + $RealExe + "  (" + (Get-Item $RealExe).Length + " bytes)") -ForegroundColor Cyan

Add-Type -AssemblyName System.Drawing

if (-not ('IconExtract' -as [type])) {
    Add-Type -TypeDefinition @'
using System;
using System.Runtime.InteropServices;

public static class IconExtract
{
    [DllImport("user32.dll", CharSet = CharSet.Unicode, SetLastError = true)]
    public static extern uint PrivateExtractIcons(
        string szFileName, int nIconIndex, int cxIcon, int cyIcon,
        IntPtr[] phicon, uint[] piconid, uint nIcons, uint flags);

    [DllImport("user32.dll", SetLastError = true)]
    public static extern bool DestroyIcon(IntPtr hIcon);
}
'@
}

function Get-IconBitmap {
    param([string]$Path, [int]$Size)
    $handles = New-Object IntPtr[] 1
    $ids     = New-Object uint32[] 1
    $n = [IconExtract]::PrivateExtractIcons($Path, 0, $Size, $Size, $handles, $ids, 1, 0)
    if ($n -lt 1 -or $handles[0] -eq [IntPtr]::Zero) { return $null }
    try {
        $ico = [System.Drawing.Icon]::FromHandle($handles[0])
        return $ico.ToBitmap()
    } finally {
        [void][IconExtract]::DestroyIcon($handles[0])
    }
}

function ConvertTo-IcoEntry {
    param([System.Drawing.Bitmap]$Bmp, [int]$Width, [int]$Height)

    $resized = New-Object System.Drawing.Bitmap($Width, $Height, [System.Drawing.Imaging.PixelFormat]::Format32bppArgb)
    $g = [System.Drawing.Graphics]::FromImage($resized)
    $g.InterpolationMode = [System.Drawing.Drawing2D.InterpolationMode]::HighQualityBicubic
    $g.PixelOffsetMode   = [System.Drawing.Drawing2D.PixelOffsetMode]::HighQuality
    $g.DrawImage($Bmp, 0, 0, $Width, $Height)
    $g.Dispose()

    $xorSize = $Width * $Height * 4
    $andRow  = [int][Math]::Ceiling($Width / 8.0)
    $andPad  = (4 - ($andRow % 4)) % 4
    $andRow += $andPad
    $andSize = $andRow * $Height

    $ms = New-Object System.IO.MemoryStream
    $bw = New-Object System.IO.BinaryWriter($ms)

    # BITMAPINFOHEADER：高度写两倍（XOR + AND 两段）
    $bw.Write([uint32]40)
    $bw.Write([int32]$Width)
    $bw.Write([int32]($Height * 2))
    $bw.Write([uint16]1)
    $bw.Write([uint16]32)
    $bw.Write([uint32]0)
    $bw.Write([uint32]($xorSize + $andSize))
    $bw.Write([int32]0); $bw.Write([int32]0)
    $bw.Write([uint32]0); $bw.Write([uint32]0)

    # XOR 像素（BGRA，自下而上）
    for ($y = $Height - 1; $y -ge 0; $y--) {
        for ($x = 0; $x -lt $Width; $x++) {
            $c = $resized.GetPixel($x, $y)
            $bw.Write([byte]$c.B); $bw.Write([byte]$c.G); $bw.Write([byte]$c.R); $bw.Write([byte]$c.A)
        }
    }
    # AND 掩码（32bpp 带 alpha，可全 0）
    $zeros = New-Object byte[] $andSize
    $bw.Write($zeros)

    $bw.Flush()
    $bytes = $ms.ToArray()
    $bw.Dispose(); $ms.Dispose(); $resized.Dispose()
    return ,$bytes
}

$sizes = @(16, 32, 48, 256)
$entries = @()
foreach ($s in $sizes) {
    $bmp = Get-IconBitmap -Path $RealExe -Size $s
    if (-not $bmp) { Write-Host ("  " + $s + "x" + $s + " 提取失败，跳过") -ForegroundColor Yellow; continue }
    $bytes = ConvertTo-IcoEntry -Bmp $bmp -Width $s -Height $s
    $entries += [pscustomobject]@{ Size = $s; Bytes = $bytes }
    Write-Host ("  " + $s + "x" + $s + " -> " + $bytes.Length + " bytes") -ForegroundColor Green
    $bmp.Dispose()
}
if (-not $entries) { throw "一个尺寸都没提取到" }

# 组装 ICO 文件头 + 目录项 + 数据
$count = $entries.Count
$offset = 6 + 16 * $count
$fs = [System.IO.File]::Create($IcoPath)
$w = New-Object System.IO.BinaryWriter($fs)
$w.Write([uint16]0); $w.Write([uint16]1); $w.Write([uint16]$count)
foreach ($e in $entries) {
    $dim = if ($e.Size -ge 256) { 0 } else { $e.Size }
    $w.Write([byte]$dim); $w.Write([byte]$dim)
    $w.Write([byte]0); $w.Write([byte]0)
    $w.Write([uint16]1); $w.Write([uint16]32)
    $w.Write([uint32]$e.Bytes.Length)
    $w.Write([uint32]$offset)
    $offset += $e.Bytes.Length
}
foreach ($e in $entries) { $w.Write($e.Bytes) }
$w.Flush(); $w.Dispose(); $fs.Dispose()

Write-Host ""
Write-Host ("ICO 已生成: " + $IcoPath + "  " + (Get-Item $IcoPath).Length + " bytes  含 " + $count + " 个尺寸") -ForegroundColor Cyan

# 自检：能被 GDI+ 读回来才算合格
try {
    $test = New-Object System.Drawing.Icon($IcoPath)
    Write-Host ("自检通过：GDI+ 可读取，默认尺寸 " + $test.Width + "x" + $test.Height) -ForegroundColor Green
    $test.Dispose()
} catch {
    Write-Host ("自检失败：" + $_.Exception.Message) -ForegroundColor Red
}
```

**做什么**：用 `PrivateExtractIcons` 按 16/32/48/256 四个尺寸取图标 → 每个尺寸重采样并编码成 ICO 内的 DIB 条目 → 拼成标准 `.ico` → 用 `System.Drawing.Icon` 反读自检。
**预期输出**：

```text
源文件: C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\ksolaunch.exe  (… bytes)
  16x16 -> … bytes
  32x32 -> … bytes
  48x48 -> … bytes
  256x256 -> … bytes

ICO 已生成: C:\Users\YEHY\Desktop\wps-guard-build\src\wps.ico  … bytes  含 4 个尺寸
自检通过：GDI+ 可读取，默认尺寸 32x32
```

**失败怎么办**：
- `找不到源 exe` → 源路径写错。注意**第一次替换之前**用原版 `ksolaunch.exe`；**替换之后**源要用 `ksolaunch.real.exe`，重跑时显式指定：`.\Extract-WpsIcon.ps1 -RealExe "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.real.exe"`。
- `一个尺寸都没提取到` → 该 exe 内没有图标资源。此时跳过 `/win32icon:` 编译，接受默认图标，或从 `office6\wpsoffice.exe` 提图标。
- `自检失败` → ICO 结构写错，重跑整段（`$entries` 是脚本内变量，必须整段重跑，单独跑组装段会拿到空数组）。

### 4.5 守卫壳 C# 源码全文（可直接编译）

保存为 `%USERPROFILE%\Desktop\wps-guard-build\src\WpsLaunchGuard.cs`。**这是本机实测通过、正在运行的版本（v2）。**

```csharp
using System;
using System.Diagnostics;
using System.IO;
using System.Text;
using System.Text.RegularExpressions;

internal static class WpsLaunchGuard
{
    // 判定方式：按空白切分参数，逐 token 精确比对（去掉前导 - 或 / 后比较）。
    // 绝不用"子串包含"—— 两次参数误拦事故（/prometheus、from=taskbar）：
    //   /prometheus   正常启动标志，曾被误拦，表现为点图标毫无反应
    //   from=taskbar  任务栏图标，曾被 from=task 的子串匹配误拦，表现为任务栏图标失灵
    // 精确 token 比对可以彻底避免这类误伤。
    private static readonly string[] BlockedCores =
    {
        "wpsupdate",
        "createtask",
        "repairtask",
        "from=task",
        "source=task"
    };

    private static bool IsBlocked(string argsJoined)
    {
        if (string.IsNullOrEmpty(argsJoined)) return false;

        foreach (var raw in argsJoined.Split(new[] { ' ', '\t', '\r', '\n' }, StringSplitOptions.RemoveEmptyEntries))
        {
            string core = raw.TrimStart('-', '/').ToLowerInvariant();

            foreach (var b in BlockedCores)
                if (core == b) return true;

            // /from=autostart_after_install 这类：安装器装完的自我拉起
            if (core.Contains("autostart")) return true;
        }
        return false;
    }

    private static string LogPath
    {
        get
        {
            return Path.Combine(
                Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
                @"Kingsoft\wps-guard.log");
        }
    }

    private static void Log(string msg)
    {
        try
        {
            string p = LogPath;
            var fi = new FileInfo(p);
            if (fi.Exists && fi.Length > 262144) fi.Delete();
            File.AppendAllText(p,
                DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss") + " | " + msg + Environment.NewLine,
                Encoding.UTF8);
        }
        catch { }
    }

    private static int Main(string[] args)
    {
        var sb = new StringBuilder();
        foreach (var a in args) sb.Append(a).Append(' ');
        string joined = sb.ToString().Trim();

        if (IsBlocked(joined))
        {
            Log("BLOCKED  args=[" + joined + "]");
            return 0;   // 静默丢弃更新/自启请求
        }

        string dir = null;
        try { dir = Path.GetDirectoryName(typeof(WpsLaunchGuard).Assembly.Location); }
        catch { }

        string target = ResolvePortal(dir);
        if (target == null)
        {
            Log("NO-TARGET args=[" + joined + "] dir=[" + dir + "]");
            return 0;
        }

        try
        {
            var psi = new ProcessStartInfo(target)
            {
                UseShellExecute = false,
                WorkingDirectory = Path.GetDirectoryName(target),
                Arguments = joined
            };
            Process.Start(psi);
            Log("LAUNCH   args=[" + joined + "] -> " + target);
        }
        catch (Exception ex)
        {
            Log("FAIL     args=[" + joined + "] target=[" + target + "] err=" + ex.Message);
        }
        return 0;
    }

    private static string ResolvePortal(string root)
    {
        if (string.IsNullOrEmpty(root)) return null;
        try
        {
            string best = null;
            Version bestVer = null;
            foreach (var d in Directory.GetDirectories(root))
            {
                var name = Path.GetFileName(d);
                if (!Regex.IsMatch(name, @"^\d+(\.\d+)+$")) continue;
                Version v;
                if (!Version.TryParse(name, out v)) continue;

                string[] cands =
                {
                    Path.Combine(d, "office6", "wpsoffice.exe"),
                    Path.Combine(d, "office6", "wps.exe")
                };
                foreach (var c in cands)
                {
                    if (!File.Exists(c)) continue;
                    if (bestVer == null || v > bestVer) { bestVer = v; best = c; }
                    break;
                }
            }
            if (best != null) return best;

            // 最后一次回退：原版启动器
            var real = Path.Combine(root, "ksolaunch.real.exe");
            if (File.Exists(real)) return real;
        }
        catch { }
        return null;
    }
}
```

**源码要点逐条对照**（想改代码前务必读完）：

| 行号区 | 代码 | 作用 | 改错后果 |
|---|---|---|---|
| `BlockedCores` | `wpsupdate` / `createtask` / `repairtask` / `from=task` / `source=task` | 五个精确 token 黑名单 | 漏任何一个，对应自启通道打开 |
| `IsBlocked` 首行 | `raw.Split(' ','\t','\r','\n')` | 按空白切分，逐 token 审 | 改回整串 `Contains` → 复现事故二（任务栏图标失灵） |
| `TrimStart('-','/')` | 去掉前导 `-` / `/` | 让 `-createtask` 与 `createtask` 等价 | 少了这步，`/wpsupdate` 匹配不上 |
| `core == b` | 全等比较 | 唯一的匹配方式 | 换成 `Contains` 即灾难 |
| `core.Contains("autostart")` | 仅对**单个 token** 做包含 | 拦 `/from=autostart_after_install` | 若对整串做，`/prometheus` 之外的一切都可能被误伤 |
| `return 0` | 静默退出码 0 | 计划任务看到「成功」，不再重试 | 返回非 0 会让任务计划反复重试 |
| `LogPath` | `%LOCALAPPDATA%\Kingsoft\wps-guard.log` | 所有调用留痕，验证全靠它 | 少了它，第 8 章没法判读 |
| `Log` 里 `> 262144 就删` | 日志自轮转 | 防止日志无限长 | 长期不轮转会积累到几十 MB |
| `ResolvePortal` | 版本号 `^\d+(\.\d+)+$` 取最大 | 多版本共存时开最新版 | 误匹配目录名会让图标打不开 |
| `UseShellExecute = false` | 直接 CreateProcess 转发 | 保留完整参数与工作目录 | 改成 true 会丢参数分隔 |

### 4.6 编译（csc，必须带 /win32icon）

```powershell
$W = "$env:USERPROFILE\Desktop\wps-guard-build"
$csc = @(
    "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe",
    "$env:WINDIR\Microsoft.NET\Framework\v4.0.30319\csc.exe"
) | Where-Object { Test-Path $_ } | Select-Object -First 1
"编译器: $csc"

$ico = "$W\src\wps.ico"
$out = "$W\ksolaunch.guard.exe"
if (Test-Path $out) { Remove-Item $out -Force }

$cscArgs = @('/nologo','/target:winexe','/optimize+','/platform:anycpu',"/out:$out")
if (Test-Path $ico) { $cscArgs += "/win32icon:$ico" } else { Write-Host '警告：没有 wps.ico，将编成无图标版本' -ForegroundColor Yellow }
$cscArgs += "$W\src\WpsLaunchGuard.cs"

& $csc @cscArgs
"---"
"产物: $out  $((Get-Item $out).Length) 字节  图标: $(if (Test-Path $ico) { '已嵌入' } else { '未嵌入' })"
```

**做什么**：找系统自带的 .NET Framework 4 编译器，以「Windows 无控制台程序」为目标编译，并把 `wps.ico` 作为 win32 资源图标嵌入。
**预期输出**：

```text
编译器: C:\WINDOWS\Microsoft.NET\Framework64\v4.0.30319\csc.exe
Microsoft (R) Visual C# Compiler version 4.8.…
---
产物: C:\Users\YEHY\Desktop\wps-guard-build\ksolaunch.guard.exe  292864 字节  图标: 已嵌入
```

`/target:winexe` 下 csc 输出 0 条错误即成功（无警告是正常的）。

> **体积不作为判据**：带图标的守卫壳本机实测 **292,864 字节**，不带图标 **7,168 字节**，相差 40 倍；换了图标资源这个数字还会变。判断「壳是否在位」只看 `(Get-Item $out).VersionInfo.OriginalFilename`（守卫壳是 `ksolaunch.guard.exe`，原版是 `ksolaunch.exe`），或比对新旧两个文件的 SHA256（详见 11.4）。
**失败怎么办**：
- 找不到 `csc.exe` → 机器上缺 .NET Framework 4.x。装 Runtime 即可，或改用 `dotnet build`（需 SDK），但 `/win32icon` 参数要换成 csproj 的 `<ApplicationIcon>`。
- `error CS…` → 源码被 Markdown 弄脏（全角引号、缺分号）。用记事本重存为 UTF-8，注意 `@"Kingsoft\wps-guard.log"` 的 `@` 前缀别丢。
- 产物只有 7KB 左右（不是 292KB 量级）且图标未嵌入 → `/win32icon:` 路径里有空格但没加引号。PowerShell 数组元素整体作为一个参数传递，含空格时保持 `"/win32icon:$ico"` 这种双引号写法。
- 双击编出的 exe 闪一下就没 → 正常。它是 GUI 程序且无参数时什么都不做（走 `NO-TARGET` 或 `LAUNCH` 分支）。

### 4.7 落位顺序（严格按 1→7，顺序错了会被 ACL 拦住）

> **核心提醒：替换前必须先移除目录和文件的 DENY，否则重命名会被拦下。**
> 原因：`ksolaunch.exe` → `ksolaunch.real.exe` 是一次目录内的改名，需要安装根目录上的 `WD`（写数据/新建）+ `AD`（追加）权限；而闸3 恰好把这两个权限 DENY 掉了。所以顺序是「先解锁 → 再改名 → 再落位 → 重新上锁」。

**步骤 1：结束所有 WPS 进程**（文件被占用时改名会失败）

```powershell
$names = 'wps','wpsoffice','wpscloudsvr','wpscloudlaunch','wpscenter','wpslingxi','ksolaunch','wpsupdate','updateself','promecefpluginhost','photolaunch'
$killed = 0
Get-Process $names -ErrorAction SilentlyContinue | ForEach-Object { try { Stop-Process -Id $_.Id -Force -ErrorAction Stop; $killed++ } catch {} }
"已结束 $killed 个进程"
```

**做什么**：强停全部 WPS 相关进程（含云服务、CEF 宿主、更新器）。
**预期输出**：`已结束 3 个进程`（数字随当时状态变化，WPS 没开时是 0）。
**失败怎么办**：`已结束 0 个进程` 且随后改名仍报占用 → 有托盘进程以别的名字存活，用 `Get-Process | Where-Object { $_.Path -like "*Kingsoft*" }` 找出真实名字再停。

**步骤 2：解除安装根目录与根启动器的 DENY（关键前置）**

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$U = "$env:USERDOMAIN\$env:USERNAME"
icacls "$Root" /remove:d "$U"
icacls "$Root" /remove:d "$env:USERNAME"
if (Test-Path "$Root\ksolaunch.exe") { icacls "$Root\ksolaunch.exe" /remove:d "$U"; icacls "$Root\ksolaunch.exe" /remove:d "$env:USERNAME" }
icacls "$Root"
```

**做什么**：把之前（或上一次运行）留在安装根目录与 `ksolaunch.exe` 上的 DENY 条目清掉，恢复正常的改名权限。
**预期输出**：`已处理 0 个文件`（没有 DENY 时），或 `已处理 1 个文件`；最后一次 `icacls` 输出的 ACL 列表里**看不到 `(DENY)` 字样**。
**失败怎么办**：`Access is denied` → 用管理员窗口重跑这 4 行；这 4 行只删 DENY 条目，重复执行是安全的。

**步骤 3：把原版改名保留为 ksolaunch.real.exe（幂等）**

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$RealL = "$Root\ksolaunch.real.exe"
$RootL = "$Root\ksolaunch.exe"
if (Test-Path $RealL) {
    "已存在 ksolaunch.real.exe，跳过改名（原版已保留）"
} else {
    Move-Item -Path $RootL -Destination $RealL -Force -ErrorAction Stop
    "原版已保留为 ksolaunch.real.exe"
}
Get-ChildItem $Root -Filter 'ksolaunch*' | Select-Object Name, Length, LastWriteTime
```

**做什么**：首次执行时把原版 `ksolaunch.exe` 改名存档；已经改过就跳过（防止把守卫壳再改名成 `.real`，把原版冲掉）。
**预期输出**：

```text
原版已保留为 ksolaunch.real.exe
Name                                   Length LastWriteTime
----                                   ------ -------------
ksolaunch.exe                           …
ksolaunch.real.exe                      …
ksolaunch.VisualElementsManifest.xml    …
```

**失败怎么办**：
- `Access to the path ... is denied` → 步骤 2 没做干净，回到步骤 2 确认无 DENY，再重跑本步。
- 已经出现两个文件但 `.real` 是守卫壳（大小 5KB 左右，而不是原版的几 MB）→ 说明顺序搞反过。处理：把当前 `ksolaunch.exe` 删掉，从备份 `wps-backup\files\root-ksolaunch.exe` 恢复为 `ksolaunch.exe`，重来。

**步骤 4：把守卫壳复制进来顶替**

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
Copy-Item "$env:USERPROFILE\Desktop\wps-guard-build\ksolaunch.guard.exe" -Destination "$Root\ksolaunch.exe" -Force
Get-Item "$Root\ksolaunch.exe" | Select-Object Name, Length, LastWriteTime
```

**做什么**：把编译产物落位成新的 `ksolaunch.exe`。
**预期输出**：`Length` 与编译产物一致（带图标约 292,864 字节，不带图标约 7,168 字节），`LastWriteTime` 是刚才；`(Get-Item "$Root\ksolaunch.exe").VersionInfo.OriginalFilename` 返回 `ksolaunch.guard.exe`。**用原始文件名判断壳是否落位，不用体积。**
**失败怎么办**：`Access is denied`（权限不足） → 目录 DENY 还在（步骤 2 未生效）。先 `icacls "$Root" /remove:d "$env:USERDOMAIN\$env:USERNAME"`，再重跑。

**步骤 5：给守卫壳与根目录重新上锁（可执行，但不可改、不可删）**


## 5 闸3 ACL 封锁（核心）

### 5.1 这一闸锁什么、不锁什么

| 对象 | 位置 | 锁法 | 理由 |
|---|---|---|---|
| `office6\ksolaunch.exe` | 版本目录 | 禁执行 + 禁改 + 禁删 | 更新器调用它来启动更新流程 |
| `wtoolex\wpsupdate.exe` | 版本目录 | 禁执行 + 禁改 + 禁删 | 自我重建任务（`-createtask`/`-repairtask`）的元凶 |
| `wtoolex\updateself.exe` | 版本目录 | 禁执行 + 禁改 + 禁删 | 自我更新器（正确拼写 **updateself.exe**） |
| `wtoolex\updatepolicy.exe` | 版本目录 | 禁执行 + 禁改 + 禁删 | 更新策略判定 |
| `%LOCALAPPDATA%\Kingsoft\WPS Office` | 安装根 | 禁新建文件/子目录 | 挡住「往目录里丢新版本」 |
| `office6\wpsoffice.exe`、`office6\wps.exe` | 版本目录 | **不锁** | 这是主程序，锁了就打不开 WPS |
| 根 `ksolaunch.exe` | 安装根 | 只禁改禁删（第 4 章步骤 5） | 图标要靠它执行 |

### 5.2 权限位含义表（必须先看懂这张表再动手）

| 缩写 | 全名 | 允许的操作 | 出现在 DENY 里的效果 |
|---|---|---|---|
| `X` | Execute / Traverse | 执行程序文件、遍历目录 | 该 exe 起不来（双击报「没有关联的应用」或被直接拦下） |
| `WD` | WriteData / AddFile | 写文件内容、在目录里新建文件 | 文件内容改不动；目录里新建不了文件 |
| `AD` | AppendData / AddSubdirectory | 追加写、在目录里新建子目录 | 追加被拦；目录里新建不了子目录 |
| `WEA` | WriteExtendedAttributes | 写扩展属性、备用数据流 | 更新器写版本标记、写 `:Zone.Identifier` 之类的动作被拦 |
| `WA` | WriteAttributes | 改文件属性（只读位、隐藏位等） | 改属性失败，`Set-ItemProperty` 之类动作被拦 |
| `DE` | Delete | 删除文件/子项 | 删不掉（`del`、`Remove-Item` 都报权限不足） |
| `RC` | ReadControl | 读安全描述符（ACL） | **故意不下**，因为 ACL 读不出来时资源管理器会判文件损坏 |
| `RD` | ReadData | 读文件内容 | **故意不下**，主程序要靠它加载，且第 3 章要算哈希 |

**组合方式固定为三种，照抄即可：**

```text
禁执行 + 禁改 + 禁删 : (X,WD,AD,WEA,WA,DE)      ← 4 个更新器载荷
可执行 + 禁改 + 禁删 : (WD,AD,WEA,WA,DE)         ← 根 ksolaunch.exe / ksolaunch.real.exe
目录禁新建子项       : (WD,AD)                    ← 安装根目录、WPS Cloud Files\update
```

### 5.3 铁律：绝不要用 icacls 的简写 W

`icacls` 支持简写权限，例如 `(W)`、`(F)`、`(M)`、`(RX)`。**这里必须用上面的精确位串，绝不要写 `(W)`。**

原因（实测结论，不是理论）：**`W` 是泛型写权限（GENERIC_WRITE），下 DENY 时会连带把 `READ_CONTROL` 一起 DENY 掉。** 后果非常具体：

- 文件连「读」都做不了 —— 资源管理器打不开属性、看不到大小；
- 依赖 ACL 检查的程序直接判文件异常，**WPS 主界面起不来**；
- `Get-FileHash` 报权限不足，第 3 章的校验链断裂；
- 更麻烦的是：一旦 ACL 不可读，你想用 `icacls /remove:d` 把它撤掉，都会因为读不出安全描述符而卡住。

对照表（记住这一行就够）：

| 写法 | 实际效果 | 结论 |
|---|---|---|
| `/deny "%USERDOMAIN%\%USERNAME%:(W)"` | 泛型写 DENY，连带 `READ_CONTROL` | **事故写法，禁用** |
| `/deny "%USERDOMAIN%\%USERNAME%:(WD,AD,WEA,WA,DE)"` | 精确：只拦写与删，读和执行保留 | 本手册写法 |

### 5.6 复核判读：行为优先，掩码只作参考

> 这一节专门解决一个真实踩过的坑：**配置完全正确时，`icacls` 也会把精确掩码打印成 `(DENY)(W,D)` 这类简写**。如果拿显示形态当判据，就会把正确配置误判成「用了泛型 `W`」，然后去跑第 9 章的全量 reset —— 那才是真正把系统弄坏的操作。

#### 5.6.1 为什么显示形态靠不住（本机实测对照表）

| 我们下的位串 | `icacls` 实际打印 | `Get-Acl` 的 `FileSystemRights` | 数值掩码 |
|---|---|---|---|
| `(X,WD,AD,WEA,WA,DE)`（4 个载荷） | `(DENY)(W,D,X)` | `Traverse, Write, Delete` | `0x00010136`（65846） |
| `(WD,AD,WEA,WA,DE)`（根启动器） | `(DENY)(W,D)` | `Write, Delete` | `0x00010116`（65814） |
| `(WD,AD)`（目录） | `(DENY)(S,WD,AD)` | `CreateFiles, CreateDirectories` | `0x00000006`（6） |

三行都对应**正确配置**。结论很直接：`(DENY)(W,D,X)` 与 `(DENY)(W,D)` 是精确掩码被合成显示的结果，**不是**泛型写；真正下错成 `(W)` 时，打印出来是光秃秃的 `(DENY)(W)`，掩码会是 `0x40000000` 量级的泛型位，而不是上面这三个数。

#### 5.6.2 第一段：行为判定（权威，优先看这个）

```powershell

"① 载荷应当被拦下（不可执行）"

    catch { "PASS  执行被拦: $(Split-Path $f -Leaf)" }
}

"② 守卫壳应当可读、且禁止写入"

$probe = "$Root\_probe_$([guid]::NewGuid().ToString('N').Substring(0,4))"

```

**做什么**：三条行为探针 —— 载荷被执行是否被拦、守卫壳是否「可读但写不进」、安装根是否新建不了。探针若真的建出目录会立刻删掉。
**预期输出**（本机实测原文）：

```text
① 载荷应当被拦下（不可执行）
PASS  执行被拦: ksolaunch.exe
PASS  执行被拦: wpsupdate.exe
PASS  执行被拦: updateself.exe
PASS  执行被拦: updatepolicy.exe
② 守卫壳应当可读、且禁止写入
PASS  可读: ksolaunch.exe
PASS  写入被拦: ksolaunch.exe
③ 安装根应当禁止新建
PASS  新建被拦: C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office
```

**失败怎么办**：任一行 `FAIL` → 记下是哪一个对象，回到 5.4 补下对应命令（`仍可执行` 补 `(X,WD,AD,WEA,WA,DE)`；`仍可写` 补 `(WD,AD,WEA,WA,DE)`；`仍可新建` 补目录 `(WD,AD)`）。`读取失败` 属另一类问题，见 5.6.4 第 3 行。

#### 5.6.3 第二段：掩码判定（辅助，只在需要交叉验证时用）

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName
foreach ($p in @("$Ver\office6\ksolaunch.exe","$Ver\wtoolex\wpsupdate.exe","$Ver\wtoolex\updateself.exe","$Ver\wtoolex\updatepolicy.exe","$Root\ksolaunch.exe","$Root")) {
    if (-not (Test-Path $p)) { continue }
    "### $p"
    (Get-Acl $p).Access | Where-Object AccessControlType -eq 'Deny' | ForEach-Object {
        "  deny[{0}]  mask=0x{1:X8}  rights=[{2}]" -f $_.IdentityReference, $_.FileSystemRights.value__, $_.FileSystemRights
    }
}
```

**做什么**：用 `Get-Acl` 读出每一条 DENY 的 `FileSystemRights` 与**数值掩码**（`FileSystemRights.value__`）。数值掩码是唯一不受显示合成影响的字段。
**预期输出**（本机实测原文；每条 DENY 的**重复条数**取决于历史上执行过几次 `icacls /deny`，本机 `office6\ksolaunch.exe` 上是 3 条，属正常）：

```text
### C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\office6\ksolaunch.exe
  deny[DESKTOP-ASACLVM\YEHY]  mask=0x00010136  rights=[Traverse, Write, Delete]
### C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\wtoolex\wpsupdate.exe
  deny[DESKTOP-ASACLVM\YEHY]  mask=0x00010136  rights=[Traverse, Write, Delete]
### C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\wtoolex\updateself.exe
  deny[DESKTOP-ASACLVM\YEHY]  mask=0x00010136  rights=[Traverse, Write, Delete]
### C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\wtoolex\updatepolicy.exe
  deny[DESKTOP-ASACLVM\YEHY]  mask=0x00010136  rights=[Traverse, Write, Delete]
### C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\ksolaunch.exe
  deny[DESKTOP-ASACLVM\YEHY]  mask=0x00010116  rights=[Write, Delete]
### C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office
  deny[DESKTOP-ASACLVM\YEHY]  mask=0x00000006  rights=[CreateFiles, CreateDirectories]
```

**判读表**：

| 掩码 | 含义 | 结论 |
|---|---|---|
| `0x00010136` | `X + WD + AD + WEA + WA + DE` | 4 个载荷的正确状态 |
| `0x00010116` | `WD + AD + WEA + WA + DE` | 根启动器的正确状态 |
| `0x00000006` | `WD + AD` | 目录的正确状态 |
| `0x40000000` 量级 | 泛型写（`GENERIC_WRITE`） | **真事故**，按 9.1 撤掉重下 |

**失败怎么办**：
- 打印出来是 `rights=[Write, Delete]` 而我们下的是 6 个位 → 正常，`Write` 是合成名，看 mask 那一列。
- 同一条 DENY 重复出现多次 → 正常（每次 `icacls /deny` 追加一条），不影响效果；`icacls /remove:d` 会一次清空所有 DENY。
- `mask=` 那列不是上表三个值之一 → 才需要处理，见 5.6.4。

#### 5.6.4 第三段：什么情况才回滚

| 观察到的现象 | 是否执行 9.1 回滚 | 正确动作 |
|---|---|---|
| 行为判定全 `PASS`，`icacls` 显示 `(DENY)(W,D,X)` | **否** | 什么都不做，这是正确配置的正常显示 |
| 行为判定全 `PASS`，`Get-Acl` 显示 `Write, Delete` | **否** | 看 mask 列确认是 `0x00010116` 即可 |
| 行为判定第 ② 步 `读取失败` | **是** | 9.1 撤 DENY → 5.4 用精确位串重下 |
| 载荷 `仍可执行` / 目录 `仍可新建` | **否** | 补下对应命令，不必回滚 |
| `mask` 为 `0x40000000` 量级（泛型写） | **是** | 9.1 撤 DENY → 5.4 重下 |

**一句话**：**只有「行为验证失败」才需要回滚；单纯显示形态不构成回滚理由。**

### 5.7 上锁前后的行为对照（用来向别人解释这套方案）

| 场景 | 上锁前 | 上锁后 |
|---|---|---|
| 计划任务到点触发 | 拉起 `ksolaunch.exe /wpsupdate …` → WPS 后台起 | 守卫壳识别 token → 静默退出，0 进程 |
| 更新器执行 `-createtask` | 计划任务被重新创建 | `wpsupdate.exe` 起不来 → 建不成 |
| 更新器执行 `-repairtask` | `run repair schd exec success` | 同上，修复流程没有执行载体 |
| 安装器装完 `/from=autostart_after_install` | WPS 被自动拉起 | 守卫壳识别 `autostart` → 静默退出 |
| 双击桌面图标 | 正常打开 | **仍然正常打开**（转发到 `wpsoffice.exe`） |
| 开始菜单 / 任务栏 | 正常打开 | **仍然正常打开** |

## 6 闸1 计划任务处理

> 顺序上建议在闸3、闸4 **之后**做这一闸：先让「重建的手」失效（闸3、闸4），再来拆「现有的地基」（闸1）。反过来做的话，中间这段时间里更新器有机会把任务重建回来。

### 6.1 先把真实任务名枚举出来（名字带用户名，别猜）

```cmd
schtasks /query /fo LIST /v | findstr /i "WpsUpdate WpsUpdateTask WpsUpdateLogonTask ksolaunch"
```

**做什么**：从全部任务的详细列表里筛出与 WPS 更新相关的行。
**预期输出**（本机实测形态）：

```text
任务名:                            \WpsUpdateTask_YEHY
要运行的任务:                      %LOCALAPPDATA%\Kingsoft\WPS Office\ksolaunch.exe /wpsupdate -from=task -source=task
任务名:                            \WpsUpdateLogonTask_YEHY
要运行的任务:                      %LOCALAPPDATA%\Kingsoft\WPS Office\ksolaunch.exe /wpsupdate -from=task -source=task
```

**失败怎么办**：一条都没有 → 两种情况：① 任务已被删（闸1 无活可干，直接进第 7 章）；② `findstr` 因中文编码匹配不上。改用 PowerShell 枚举（更可靠）：

```powershell
Get-ScheduledTask | Where-Object { ($_.Actions | ForEach-Object { "$($_.Execute) $($_.Arguments)" }) -join ' ' -match 'ksolaunch|wpsupdate|Kingsoft' } |
    Select-Object TaskPath, TaskName, State, @{n='Action';e={ ($_.Actions | ForEach-Object { "$($_.Execute) $($_.Arguments)" }) -join ' | ' }} | Format-List
```

### 6.2 禁用两条任务

```cmd
schtasks /Change /TN "WpsUpdateTask_%USERNAME%" /DISABLE
schtasks /Change /TN "WpsUpdateLogonTask_%USERNAME%" /DISABLE
```

**做什么**：把两条任务置为「已禁用」。禁用不动任务定义，随时可以 `/ENABLE` 恢复，是最轻的一步。
**预期输出**：

```text
成功: 成功更改了计划任务“WpsUpdateTask_YEHY”的参数。
成功: 成功更改了计划任务“WpsUpdateLogonTask_YEHY”的参数。
```

**失败怎么办**：
- `错误: 系统找不到指定的任务名。` → 任务名里没有用户名后缀，或后缀不是当前用户名。回 6.1 抄准名字，用 `schtasks /Change /TN "\完整任务名" /DISABLE`。
- `错误: Access is denied（权限不足）` → 任务 DACL 只给了普通用户读权限。**必须用管理员执行**，见 6.4。

### 6.3 删除两条任务

```cmd
schtasks /Delete /TN "WpsUpdateTask_%USERNAME%" /F
schtasks /Delete /TN "WpsUpdateLogonTask_%USERNAME%" /F
```

**做什么**：彻底移除任务定义。`/F` 表示不再交互确认。
**预期输出**：

```text
成功: 成功删除了计划任务“WpsUpdateTask_YEHY”。
成功: 成功删除了计划任务“WpsUpdateLogonTask_YEHY”。
```

**失败怎么办**：
- `错误: Access is denied（权限不足）` → 同 6.2，走 6.4。
- 删掉了但过一段时间又出现 → 这是第二层机制在起作用：`wpsupdate.exe -createtask` 重建了任务。说明闸3（第 5 章）没生效，回第 5 章 5.5 自检。
- 想保留任务但让它永远不触发，可以只禁用不删除（做完 6.2 就停手）。两种做法都成立：删除更干净，禁用更好回退。

### 6.4 DACL 受限时的管理员做法（Access is denied 的标准处理）

WPS 创建这两条任务时，任务安全描述符可能只给当前用户「读 + 执行」，改和删都需要更高权限。表现就是 6.2/6.3 一路 `Access is denied`。处理方式分三步：

**第一步：开一个管理员 PowerShell（UAC 提示点「是」）**

```powershell
Start-Process powershell -Verb RunAs
```

**做什么**：弹出提权窗口。所有闸1、闸2 的命令都在这个窗口里执行。
**预期输出**：新窗口标题栏显示「管理员: Windows PowerShell」。
**失败怎么办**：账户不在管理员组，需要由管理员账户登录后操作；或者用 `runas /user:Administrator powershell`。

**第二步：在管理员窗口里禁 + 删**

```cmd
schtasks /Change /TN "WpsUpdateTask_YEHY" /DISABLE
schtasks /Change /TN "WpsUpdateLogonTask_YEHY" /DISABLE
schtasks /Delete /TN "WpsUpdateTask_YEHY" /F
schtasks /Delete /TN "WpsUpdateLogonTask_YEHY" /F
```

**做什么**：同样的四步，提权后执行。
**预期输出**：四条全部 `成功: …`。
**失败怎么办**：仍报权限不足 → 任务的所有者是 `SYSTEM` 且 DACL 里没给 Administrators。用 PowerShell 拿所有权后再删：

```powershell
$t = Get-ScheduledTask -TaskName 'WpsUpdateTask_YEHY' -TaskPath '\'
$sd = $t.GetSecurityDescriptorSddlForm('All')
$sd | Set-Content "$env:USERPROFILE\Desktop\wps-backup\tasks\sddl-WpsUpdateTask.txt"
# 记录原 SDDL 后，用 SYSTEM 计划任务方式删除（SchTasks /Delete 由 SYSTEM 执行时天然有权限）
schtasks /Create /TN "_wps_del_once" /TR "cmd /c schtasks /Delete /TN WpsUpdateTask_YEHY /F" /SC ONCE /ST 23:59 /RU SYSTEM /RL HIGHEST /F
schtasks /Run /TN "_wps_del_once"
```

**做什么**：先用 SYSTEM 身份跑一次删除，再把临时任务清掉。原 SDDL 已落盘，回退时能对照。
**预期输出**：`成功: 尝试运行 "_wps_del_once"。`
**失败怎么办**：SYSTEM 也删不掉说明任务被组策略接管（域环境）。这种情况以「禁用」为准即可，删除不是必要条件。

**第三步：清理临时任务**

```cmd
schtasks /Delete /TN "_wps_del_once" /F
```

**做什么**：把上一步的临时载体删掉，不留痕。
**预期输出**：`成功: 成功删除了计划任务"_wps_del_once"。`
**失败怎么办**：`找不到指定的任务名` 说明本来就没建成，忽略即可。

### 6.5 确认结果

```powershell
$U = $env:USERNAME
foreach ($n in @("WpsUpdateTask_$U","WpsUpdateLogonTask_$U")) {
    $t = Get-ScheduledTask -TaskName $n -TaskPath '\' -ErrorAction SilentlyContinue
    if ($null -eq $t) { "已删除  $n" } else { "仍存在  $n  状态=$($t.State)" }
}
"--- 全盘扫描残留 ---"
Get-ScheduledTask | Where-Object { ($_.Actions | ForEach-Object { "$($_.Execute) $($_.Arguments)" }) -join ' ' -match 'ksolaunch|wpsupdate|Kingsoft' } |
    Select-Object TaskName, State
```

**做什么**：逐条确认两条任务的状态，并全盘扫一遍是否还有别的 WPS 触发项。
**预期输出**：

```text
已删除  WpsUpdateTask_YEHY
已删除  WpsUpdateLogonTask_YEHY
--- 全盘扫描残留 ---
（无输出）
```

**失败怎么办**：`仍存在 … 状态=Ready` → 6.2 的禁用没生效，重跑。全盘扫描出现别的任务名（如 `WpsCloudSyncTask_*`）→ 同样处理：先 `Export-ScheduledTask` 备份，再禁用，再删除。

## 7 闸2 服务处理

> `wpscloudsvr` 是 WPS 云文档服务。它本身不直接负责「开机自启 WPS 界面」，但会随开机拉起、并可能触发更新检查，属于需要一起收掉的地基。**这一步需要管理员。**

### 7.1 先看现状并留档

```cmd
sc.exe qc wpscloudsvr
sc.exe query wpscloudsvr
```

**做什么**：读服务配置（启动类型、二进制路径）与当前运行状态。
**预期输出**：

```text
SERVICE_NAME: wpscloudsvr
        TYPE               : 10  WIN32_OWN_PROCESS
        START_TYPE         : 2   AUTO_START
        ...
SERVICE_NAME: wpscloudsvr
        STATE              : 4  RUNNING
```

**失败怎么办**：`[SC] OpenService 失败 1060:` → 该版本没有这个服务，第 7 章整章跳过，不影响整体效果。

### 7.2 改成禁用启动

```cmd
sc.exe config wpscloudsvr start= disabled
```

**做什么**：把启动类型从 `AUTO_START(2)` 改成 `DISABLED(4)`，开机不再拉起。
**预期输出**：

```text
[SC] ChangeServiceConfig 成功
```

**失败怎么办**：
- `[SC] OpenService 失败 5:` → 权限不足，用管理员窗口重跑。
- `Access is denied`（权限不足） → 同上。
- 语法要点：`start=` 后面**必须有一个空格**再写值（`start= disabled`）。写成 `start=disabled` 会报 `参数错误`。

### 7.3 停掉正在跑的实例

```cmd
sc.exe stop wpscloudsvr
```

**做什么**：立即停止服务进程，让配置马上生效。
**预期输出**：

```text
SERVICE_NAME: wpscloudsvr
        STATE              : 3  STOP_PENDING
                              （而后）
        STATE              : 1  STOPPED
```

**失败怎么办**：`[SC] ControlService 失败 1061: 服务当前不接受控制信息` → 服务正在启动/停止中，等 10 秒重试。反复失败就强停进程：

```powershell
Get-Process wpscloudsvr -ErrorAction SilentlyContinue | Stop-Process -Force
"进程已清: " + (Get-Process wpscloudsvr -ErrorAction SilentlyContinue).Count
```

### 7.4 确认

```cmd
sc.exe qc wpscloudsvr | findstr /i "START_TYPE"
sc.exe query wpscloudsvr | findstr /i "STATE"
```

**做什么**：确认启动类型与运行状态都到位。
**预期输出**：

```text
        START_TYPE         : 4   DISABLED
        STATE              : 1   STOPPED
```

**失败怎么办**：`START_TYPE` 仍是 `2` → `sc config` 没生效，重跑 7.2 并检查是否有组策略在回写（`gpresult /h gp.html` 查「系统服务」策略）。

## 8 验证方法

> 验证分两半：**四个自启参数必须 0 进程**，**三个正常入口必须能开**。只验前半的人，最后一定会遇到「图标点了没反应」。

### 8.1 清场：先把 WPS 全关掉

```powershell
$names = 'wps','wpsoffice','wpscloudsvr','wpscloudlaunch','wpscenter','wpslingxi','ksolaunch','wpsupdate','updateself','promecefpluginhost','photolaunch','kwpsconvert'
Get-Process $names -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Sleep 4
"WPS 相关进程数: " + (Get-Process $names -ErrorAction SilentlyContinue).Count
```

**做什么**：把基线清成 0，否则「0 进程」这个判据没有意义。
**预期输出**：`WPS 相关进程数: 0`
**失败怎么办**：数字不为 0 → 有进程在重启循环里。先确认闸3 已上锁，再重跑一次；仍不为 0 就记下进程名（可能是托盘常驻），验证时改用「进程 PID 是否新增」来判断。

### 8.2 四种自启参数，逐个手工执行（都必须 0 进程）

**参数 A：计划任务的真实动作**

```powershell
$shim = "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.exe"
$before = @(Get-Process wps,wpsoffice,wpscloudsvr -ErrorAction SilentlyContinue).Count
$p = Start-Process -FilePath $shim -ArgumentList '/wpsupdate -from=task -source=task' -PassThru
$p.WaitForExit(8000) | Out-Null
Start-Sleep 3
$after = @(Get-Process wps,wpsoffice,wpscloudsvr -ErrorAction SilentlyContinue).Count
"退出码=$($p.ExitCode)  前=$before  后=$after  判定=" + $(if ($after -eq 0) { 'PASS' } else { 'FAIL' })
```

**做什么**：等价于 `\WpsUpdateTask_<用户名>` 到点触发的那一次调用。
**预期输出**：

```text
退出码=0  前=0  后=0  判定=PASS
```

**失败怎么办**：`后` 不为 0 → 守卫壳没拦下。看日志 `Get-Content "$env:LOCALAPPDATA\Kingsoft\wps-guard.log" -Tail 3`：若显示 `LAUNCH … /wpsupdate …`，说明源码里的黑名单被改坏了（`wpsupdate` 不在 `BlockedCores` 里）；若显示 `BLOCKED`，说明拦下来了但你数进程的时间点太早/太晚，把 `Start-Sleep 3` 加到 8 秒重试。

**参数 B：更新器重建任务**

```powershell
$shim = "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.exe"
$p = Start-Process -FilePath $shim -ArgumentList '-createtask' -PassThru
$p.WaitForExit(8000) | Out-Null
Start-Sleep 3
"退出码=$($p.ExitCode)  进程=" + @(Get-Process wps,wpsoffice,wpscloudsvr -ErrorAction SilentlyContinue).Count
```

**做什么**：模拟第二层机制里的 `kupdate::Execute cmd=[-createtask]`。
**预期输出**：`退出码=0  进程=0`
**失败怎么办**：进程不为 0 → 同上，检查 `-createtask` 的 token 比对（`TrimStart('-','/')` 之后应等于 `createtask`）。另外确认任务确实没被建出来：

```powershell
Get-ScheduledTask -TaskName "WpsUpdateTask_$env:USERNAME" -TaskPath '\' -ErrorAction SilentlyContinue | Select-Object TaskName, State
```

无输出 = 没被重建，符合预期。

**参数 C：更新器修复任务**

```powershell
$shim = "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.exe"
$p = Start-Process -FilePath $shim -ArgumentList '-repairtask' -PassThru
$p.WaitForExit(8000) | Out-Null
Start-Sleep 3
"退出码=$($p.ExitCode)  进程=" + @(Get-Process wps,wpsoffice,wpscloudsvr -ErrorAction SilentlyContinue).Count
```

**做什么**：模拟 `kupdate::Execute cmd=[-repairtask]` 与随后的 `run repair schd exec success`。
**预期输出**：`退出码=0  进程=0`
**失败怎么办**：同参数 B；另外检查更新日志里是否出现新的 `kupdate::Execute` 行（第 8.4 节有命令）。

**参数 D：安装器装完自启**

```powershell
$shim = "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.exe"
$p = Start-Process -FilePath $shim -ArgumentList '/prometheus /from=autostart_after_install' -PassThru
$p.WaitForExit(8000) | Out-Null
Start-Sleep 3
"退出码=$($p.ExitCode)  进程=" + @(Get-Process wps,wpsoffice -ErrorAction SilentlyContinue).Count
```

**做什么**：模拟 WPS 安装/升级完成后由安装器发起的自我拉起。
**预期输出**：`退出码=0  进程=0`
**失败怎么办**：进程不为 0 → 说明 `autostart` 判定没生效。检查源码 `if (core.Contains("autostart")) return true;` 这一行是否被删；注意 `from=autostart_after_install` 去掉前导 `/` 后仍然包含 `autostart`，这一条按 token 级包含判断是对的。

### 8.3 三次正常入口，必须都能起来

> **判据统一（先读这条，后面三段不再重复判据）**：
> 1. `Get-Process wps,wpsoffice` 的进程数 **≥ 3**；
> 2. 存在 `MainWindowTitle` 为 `WPS Office` 的主窗口进程。
>
> 具体进程数在 **3～8 之间浮动**（最小化 / 停在首页 / 打开了文档，状态不同数量就不同），**不要卡死某个数字**。

**统一判读命令（每段入口测试后跑这一条）**

```powershell
$names = 'wps','wpsoffice'
$procs = @(Get-Process $names -ErrorAction SilentlyContinue)
"进程数: " + $procs.Count + "  (判据: >= 3)"
$procs | Where-Object { $_.MainWindowTitle } | Select-Object Id, ProcessName, MainWindowTitle
```

**做什么**：数进程 + 只看带主窗口的那几个进程标题。
**预期输出**（本机实测形态，进程数会随状态浮动）：

```text
进程数: 4  (判据: >= 3)
   Id ProcessName MainWindowTitle
   -- ----------- ---------------
 8124 wpsoffice  WPS Office
```

**判读**：进程数 ≥ 3 **且** 表格里出现 `WPS Office` 这一行 = PASS。
**失败怎么办**：进程数够但标题全空 → 主窗口还在创建，等 5 秒再取一次；进程数 0 → 走下面各段的「失败怎么办」。

**入口 1：桌面图标（真实参数 `/prometheus /fromksolaunch /from=startmenu`）**

```powershell
$shim = "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.exe"
Start-Process -FilePath $shim -ArgumentList '/prometheus /fromksolaunch /from=startmenu'
Start-Sleep 12
"进程数: " + @(Get-Process wps,wpsoffice -ErrorAction SilentlyContinue).Count
```

**做什么**：等价于双击桌面 WPS 图标。
**预期输出**：`进程数: 3` 或更多（3～8 浮动），且存在标题为 `WPS Office` 的窗口 —— 两条都满足即 PASS。
**失败怎么办**：进程数 0 → 日志里看 `NO-TARGET`/`FAIL`。`LAUNCH` 有但进程没起，通常是主程序被别的安全软件拦了，属另一个问题。

**入口 2：开始菜单**

```powershell
$shim = "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.exe"
$names = 'wps','wpsoffice'
Get-Process $names -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Sleep 4
Start-Process -FilePath $shim -ArgumentList '/prometheus /fromksolaunch /from=startmenu'
Start-Sleep 12
"进程数: " + @(Get-Process $names -ErrorAction SilentlyContinue).Count
```

**做什么**：开始菜单快捷方式的参数与桌面一致（`from=startmenu`），单独验一遍确认路径无差异。
**预期输出**：进程数 ≥ 3（3～8 浮动）+ 标题含 `WPS Office` → PASS。
**失败怎么办**：同入口 1。

**入口 3：任务栏图标（关键回归项，`from=taskbar`）**

```powershell
$shim = "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.exe"
$names = 'wps','wpsoffice'

Start-Sleep 4
Start-Process -FilePath $shim -ArgumentList '/prometheus /fromksolaunch /from=taskbar'
Start-Sleep 12
```

**做什么**：专门验事故二的回归 —— `from=taskbar` 曾被 `from=task` 的子串匹配误拦，导致点任务栏图标毫无反应。
**预期输出**：进程数 ≥ 3（3～8 浮动）+ 标题含 `WPS Office` → PASS。
**失败怎么办**：0 进程 → 十有八九是有人把 token 全等换成了子串包含。检查源码，确认是 `if (core == b)` 而不是 `if (core.Contains(b))`。改回后重编译、重落位（第 4 章步骤 4～5）。

### 8.4 三条判读依据（不看界面，只看它自己留下的痕迹）

**依据一：注册表 `coldStartup`（epoch 毫秒）**

WPS 每次「冷启动」都会写一次时间戳。它是判断「有没有被偷偷拉起来」最硬的证据。

```powershell
$pairs = @(
    @{ K='HKCU:\SOFTWARE\Kingsoft\Office\6.0\wpsoffice\Application Settings'; N='coldStartup'; L='coldStartup (wpsoffice)' },
    @{ K='HKCU:\SOFTWARE\Kingsoft\Office\6.0\qing\Application Settings';      N='coldStartup'; L='coldStartup (qing)' }
)
foreach ($p in $pairs) {
    $v = (Get-ItemProperty $p.K -Name $p.N -ErrorAction SilentlyContinue).($p.N)
    if ($null -eq $v) { "{0,-26} （无值）" -f $p.L; continue }
    $t = (Get-Date '1970-01-01T00:00:00Z').AddMilliseconds([double]$v).ToLocalTime()
    "{0,-26} {1}  (raw={2})" -f $p.L, $t.ToString('yyyy-MM-dd HH:mm:ss'), $v
}
```

**做什么**：把两个 `coldStartup` 的 epoch 毫秒值翻成本地时间。
**预期输出**：

```text
coldStartup (wpsoffice)    2026-11-27 18:05:45  (raw=1794…)
coldStartup (qing)         2026-11-27 18:05:46  (raw=1794…)
```

**判读**：先记下当前时间点（称为「锚点」），然后只跑 8.2 的四个自启参数。跑完再看这两个值 —— **时间应当保持在锚点之前**。若有新值写入，说明有进程真的起来了，回 8.2 定位是哪个参数漏了。
**失败怎么办**：`（无值）` → 该组件从未启动过，本身是好消息，跳过即可。

**依据二：`%APPDATA%\kingsoft\office6\log` 最新写入时间**

```powershell
$logDir = "$env:APPDATA\kingsoft\office6\log"
if (Test-Path $logDir) {
    $newest = Get-ChildItem $logDir -Recurse -File -ErrorAction SilentlyContinue | Sort-Object LastWriteTime -Descending | Select-Object -First 3
    $newest | Select-Object LastWriteTime, Length, FullName
    "--- 更新器日志 ---"
    Get-ChildItem "$logDir\update" -Filter 'wpsupdate_*.log' -ErrorAction SilentlyContinue |
        Sort-Object LastWriteTime -Descending | Select-Object -First 3 LastWriteTime, Name
} else { "日志目录不存在：$logDir" }
```

**做什么**：找出 WPS 日志目录里最近写入的文件，以及更新器自己的日志。
**预期输出**：最新写入时间应当是**你上一次正常打开 WPS 的时刻**；跑完四个自启参数后，这个时间**不应前移**。
**判读**：时间前移 = 有进程在跑；`wpsupdate_*.log` 出现新的 `kupdate::Execute` 行 = 更新器仍在活动（说明闸3 没锁住 `wpsupdate.exe`）。
**失败怎么办**：`日志目录不存在` → 该版本日志在别处，用 `Get-ChildItem "$env:APPDATA\kingsoft" -Recurse -Directory | Select-Object FullName` 找一下；找不到就以依据一和依据三为准。

**依据三：守卫壳日志 `%LOCALAPPDATA%\Kingsoft\wps-guard.log`**

```powershell
$g = "$env:LOCALAPPDATA\Kingsoft\wps-guard.log"
if (Test-Path $g) { Get-Content $g -Tail 20 } else { "尚无日志：$g" }
```

**做什么**：读守卫壳自己写的调用记录。这是唯一能直接看到「谁调了启动器」的证据源。
**预期输出**（本机实测的真实片段）：

```text
2026-11-27 18:03:54 | LAUNCH   args=[/prometheus /fromksolaunch /from=startmenu] -> C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office\12.1.0.29690\office6\wpsoffice.exe
2026-11-27 18:04:30 | BLOCKED  args=[/wpsupdate -from=task -source=task]
2026-11-27 18:04:33 | BLOCKED  args=[-createtask]
2026-11-27 18:04:35 | BLOCKED  args=[-repairtask]
2026-11-27 18:04:46 | LAUNCH   args=[/prometheus /fromksolaunch /from=taskbar] -> C:\…\office6\wpsoffice.exe
2026-11-27 18:05:24 | BLOCKED  args=[/prometheus /from=autostart_after_install]
```

**判读**：
- `BLOCKED` 行 = 该次调用被丢弃，符合预期。
- `LAUNCH` 行 = 放行并转发，看 `from=` 的值区分是桌面/开始菜单/任务栏。
- `NO-TARGET` = 找不到主程序，图标会打不开。
- `FAIL` = 主程序起不来，后面 `err=` 是系统错误原文。

**失败怎么办**：日志里没有任何 `BLOCKED` 却也没有进程 → 说明调用的根本不是守卫壳（快捷方式还指着旧路径）。检查快捷方式目标：

```powershell
$lnk = "$env:PUBLIC\Desktop\WPS Office.lnk"
if (Test-Path $lnk) { $s = (New-Object -ComObject WScript.Shell).CreateShortcut($lnk); $s.TargetPath; $s.Arguments }
```

### 8.5 一键总验（把 8.1～8.4 合成一段）

```powershell
$shim = "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.exe"
$names = 'wps','wpsoffice','wpscloudsvr'
$block = @('/wpsupdate -from=task -source=task','-createtask','-repairtask','/prometheus /from=autostart_after_install')
$pass  = @('/prometheus /fromksolaunch /from=startmenu','/prometheus /fromksolaunch /from=taskbar')

"=== 应被拦下（0 进程）==="
foreach ($a in $block) {
    Get-Process $names -ErrorAction SilentlyContinue | Stop-Process -Force; Start-Sleep 3
    $p = Start-Process -FilePath $shim -ArgumentList $a -PassThru
    $p.WaitForExit(8000) | Out-Null; Start-Sleep 3
    $n = @(Get-Process $names -ErrorAction SilentlyContinue).Count
    "{0,-6} {1,-52} 退出码={2} 进程={3}" -f $(if($n -eq 0){'PASS'}else{'FAIL'}), $a, $p.ExitCode, $n
}
"=== 应被放行（>=3 进程 + 标题含 WPS Office）==="
foreach ($a in $pass) {
    Get-Process $names -ErrorAction SilentlyContinue | Stop-Process -Force; Start-Sleep 3
    Start-Process -FilePath $shim -ArgumentList $a | Out-Null
    Start-Sleep 12
    $procs = @(Get-Process $names -ErrorAction SilentlyContinue)
    $win = @($procs | Where-Object { $_.MainWindowTitle -like '*WPS Office*' }).Count
    $ok  = ($procs.Count -ge 3) -and ($win -ge 1)
    "{0,-6} {1,-52} 进程={2} 主窗口={3}" -f $(if($ok){'PASS'}else{'FAIL'}), $a, $procs.Count, $win
}
Get-Process $names -ErrorAction SilentlyContinue | Stop-Process -Force
"=== 守卫壳日志最后 8 行 ==="
Get-Content "$env:LOCALAPPDATA\Kingsoft\wps-guard.log" -Tail 8
```

**做什么**：6 项一轮跑完，逐项给出 PASS/FAIL。放行的两项按 8.3 的统一判据判（进程数 ≥3 **且** 有 `WPS Office` 主窗口）。
**预期输出**（进程数与主窗口计数随状态浮动，只要 PASS 即可）：

```text
=== 应被拦下（0 进程）===
PASS   /wpsupdate -from=task -source=task                    退出码=0 进程=0
PASS   -createtask                                           退出码=0 进程=0
PASS   -repairtask                                           退出码=0 进程=0
PASS   /prometheus /from=autostart_after_install             退出码=0 进程=0
=== 应被放行（>=3 进程 + 标题含 WPS Office）===
PASS   /prometheus /fromksolaunch /from=startmenu            进程=4 主窗口=1
PASS   /prometheus /fromksolaunch /from=taskbar              进程=5 主窗口=1
```
**失败怎么办**：哪一项 FAIL 就回到对应小节（8.2 的四段 / 8.3 的三段）单独复现。**任何一项 FAIL 都不要继续做第 9 章以外的操作**，先修好再谈收工。

## 9 恢复原装（五步完整回退）

> 「原装」的定义：WPS 的所有默认行为（自动更新、重建自启任务、安装后自启）全部回归，文件和 ACL 与动手前逐字节一致。
> 五步顺序不可打乱：**先解 ACL → 再还原文件 → 再重建任务 → 再恢复服务 → 最后复核**。
> 前提：第 3 章的备份齐备，特别是 `wps-backup\files\hashes-original.json` 与两条任务 XML。

### 9.1 第一步：移除所有 DENY

> **前置条件（必读）**：仅在 5.6.2 的**行为判定失败**时才执行本节。`icacls` 把精确掩码打印成 `(DENY)(W,D,X)`、或 `Get-Acl` 把 6 个位合成成 `Write, Delete`，都是**正常显示形态**，不构成执行本节的理由。误执行本节会把正确配置整体 reset，等于白做一遍。

```powershell
# 0) 先关进程，否则文件被占用
$names = 'wps','wpsoffice','wpscloudsvr','ksolaunch','wpsupdate','updateself','promecefpluginhost'
Get-Process $names -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Sleep 4

$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName
$CloudUp = "$env:LOCALAPPDATA\Kingsoft\WPS Cloud Files\update"
$U = "$env:USERDOMAIN\$env:USERNAME"

# 1) 父目录先解锁（否则后面重命名会被拦）
foreach ($d in @($Root, $CloudUp) | Where-Object { Test-Path $_ }) {
    icacls "$d" /remove:d "$U" 2>&1 | Out-Null
    icacls "$d" /remove:d "$env:USERNAME" 2>&1 | Out-Null
}
# 2) 再解锁 6 个文件对象
$targets = @(
    "$Root\ksolaunch.exe", "$Root\ksolaunch.real.exe",
    "$Ver\office6\ksolaunch.exe",
    "$Ver\wtoolex\wpsupdate.exe",
    "$Ver\wtoolex\updateself.exe",
    "$Ver\wtoolex\updatepolicy.exe"
) | Where-Object { Test-Path $_ }
foreach ($t in $targets) {
    icacls "$t" /remove:d "$U" 2>&1 | Out-Null
    icacls "$t" /remove:d "$env:USERNAME" 2>&1 | Out-Null
}
# 3) 逐个确认干净
foreach ($t in @($targets + $Root)) {
    $acl = (icacls "$t" 2>&1 | Out-String)
    "{0,-22} {1}" -f (Split-Path $t -Leaf), $(if ($acl -match 'DENY') { '仍有 DENY' } else { '干净' })
}
```

**做什么**：按「父目录 → 子文件」的顺序把每一条 DENY ACE 删掉（`/remove:d` 只删 DENY，不动允许项）。
**预期输出**：

```text
ksolaunch.exe          干净
ksolaunch.real.exe     干净
ksolaunch.exe          干净
wpsupdate.exe          干净
updateself.exe         干净
updatepolicy.exe       干净
WPS Office             干净
```

**失败怎么办**：
- 有个别行报 `Access is denied` → 该对象上已经有人用 `(W)` 泛型位下过 DENY，导致 ACL 读不出来。用管理员窗口执行 `icacls "<路径>" /reset` 把 ACL 恢复到继承状态，再核对。
- 仍显示 `仍有 DENY` → 用 `icacls "<路径>"` 看 DENY 条目里的账户名，可能不是当前用户名（例如写成 `Everyone` 或 SID）。用 `icacls "<路径>" /remove:d "Everyone"` 或按 SID 撤：`icacls "<路径>" /remove:d "*S-1-1-0"`。

### 9.2 第二步：删掉守卫壳，把原版改回来，核对哈希

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$RootL = "$Root\ksolaunch.exe"
$RealL = "$Root\ksolaunch.real.exe"
$B = "$env:USERPROFILE\Desktop\wps-backup"

if (-not (Test-Path $RealL)) {
    "ksolaunch.real.exe 不存在 —— 可能本来就是原装，跳过"
} else {
    if (Test-Path $RootL) { Remove-Item $RootL -Force -ErrorAction Stop; "守卫壳已删除" }
    Rename-Item -Path $RealL -NewName 'ksolaunch.exe' -ErrorAction Stop
    "原版已复位为 ksolaunch.exe"
}

# 核对哈希
$expect = (Get-Content "$B\files\hashes-original.json" -Raw | ConvertFrom-Json | Where-Object File -eq 'root-ksolaunch.exe').SHA256
$h = (Get-FileHash $RootL -Algorithm SHA256 -ErrorAction Stop).Hash
"当前 : $h"
"原始 : $expect"
"结论 : " + $(if ($h -eq $expect) { '一致，原装已复位' } else { '不一致，用备份覆盖' })
```

**做什么**：删掉守卫壳 → 把 `ksolaunch.real.exe` 改名回 `ksolaunch.exe` → 用备份里的原始哈希比对。
**预期输出**：

```text
守卫壳已删除
原版已复位为 ksolaunch.exe
当前 : 6A1E302155B25504DA98A6C9F0A67D837AFD850EDCD7729122B27C4DDB0D1557
原始 : 6A1E302155B25504DA98A6C9F0A67D837AFD850EDCD7729122B27C4DDB0D1557
结论 : 一致，原装已复位
```

**失败怎么办**：
- `Remove-Item` 报权限不足 → 9.1 没做干净。回 9.1 确认 `WPS Office` 目录显示「干净」。
- 哈希不一致 → 用备份直接覆盖（这是最稳的收尾）：

```powershell
Copy-Item "$B\files\root-ksolaunch.exe" -Destination $RootL -Force
(Get-FileHash $RootL -Algorithm SHA256).Hash
```

- 想让 Windows 自己修回来：`wps.exe` 自带的修复安装会把 `ksolaunch.exe` 重新释放，但会一并重置 ACL 与任务，等于回到「全新安装」状态 —— 只有备份也丢了才用这招。

### 9.3 第三步：用备份 XML 重建两条计划任务

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"
$U = $env:USERNAME

# 确保计划任务服务在跑
$svc = Get-Service Schedule
if ($svc.Status -ne 'Running') { Start-Service Schedule; Start-Sleep 2 }
"计划任务服务: " + (Get-Service Schedule).Status

foreach ($n in @("WpsUpdateTask_$U","WpsUpdateLogonTask_$U")) {
    $xml = "$B\tasks\$n.xml"
    if (-not (Test-Path $xml)) { "缺备份，跳过: $n"; continue }
    try {
        Register-ScheduledTask -Xml (Get-Content $xml -Raw) -TaskName $n -TaskPath '\' -Force -ErrorAction Stop | Out-Null
        "已重建: $n"
    } catch {
        $exist = Get-ScheduledTask -TaskName $n -TaskPath '\' -ErrorAction SilentlyContinue
        if ($exist) { "重建被拒（DACL 限制），但任务已存在，状态=$($exist.State): $n" }
        else { "重建失败: $n  ->  $($_.Exception.Message)" }
    }
}
Get-ScheduledTask -TaskName "WpsUpdateTask_$U","WpsUpdateLogonTask_$U" -TaskPath '\' -ErrorAction SilentlyContinue | Select-Object TaskName, State
```

**做什么**：把 3.2 备份的 XML 原样注册回去（`-Force` 覆盖同名任务）。
**预期输出**：

```text
计划任务服务: Running
已重建: WpsUpdateTask_YEHY
已重建: WpsUpdateLogonTask_YEHY
TaskName                 State
--------                 -----
WpsUpdateTask_YEHY       Ready
WpsUpdateLogonTask_YEHY  Ready
```

**失败怎么办**：
- `重建被拒（DACL 限制），但任务已存在` → 这是**正常结果**。这两条任务的 DACL 可能只给普通用户读权限，覆盖注册需要管理员；任务既然已经在册，原装状态就满足了。
- `重建失败` 且任务不在册 → 用管理员窗口重跑本段。
- XML 报结构错误 → 用 3.2 方法 B 的 `schtasks` 版 XML 试：把文件里的 `<?xml version="1.0" encoding="UTF-16"?>` 改成 `<?xml version="1.0" encoding="UTF-8"?>` 后重试。
- `Start-Service Schedule` 失败 → 服务被禁用过，先 `sc.exe config Schedule start= auto` 再启动。

### 9.4 第四步：服务恢复为手动

```cmd
sc.exe config wpscloudsvr start= demand
sc.exe qc wpscloudsvr | findstr /i "START_TYPE"
```

**做什么**：把 `wpscloudsvr` 从 `DISABLED` 改回 `DEMAND_START`（手动）。**为什么是 demand 而不是 auto**：`demand` 是这类辅助服务的常规出厂值 —— 用时拉起、不用时安静，与「原装」的可观测行为一致。若你 3.5 备份里 `START_TYPE` 是 `2 AUTO_START`，就把 `demand` 换成 `auto` 严格复原：

```cmd
sc.exe config wpscloudsvr start= auto
```

**预期输出**：

```text
[SC] ChangeServiceConfig 成功
        START_TYPE         : 3   DEMAND_START
```

**失败怎么办**：`[SC] OpenService 失败 5:` → 权限不足，管理员窗口重跑。服务不存在（1060）→ 跳过本步。

### 9.5 第五步：逐项复核

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName
$B = "$env:USERPROFILE\Desktop\wps-backup"
$orig = Get-Content "$B\files\hashes-original.json" -Raw | ConvertFrom-Json
$map = @{
  'root-ksolaunch.exe'       = "$Root\ksolaunch.exe"
  'office6-ksolaunch.exe'    = "$Ver\office6\ksolaunch.exe"
  'wtoolex-wpsupdate.exe'    = "$Ver\wtoolex\wpsupdate.exe"
  'wtoolex-updateself.exe'   = "$Ver\wtoolex\updateself.exe"
  'wtoolex-updatepolicy.exe' = "$Ver\wtoolex\updatepolicy.exe"
}
"=== 1. 哈希复核 ==="
foreach ($r in $orig) {
    $p = $map[$r.File]
    if (-not $r.Exists -or -not (Test-Path $p)) { "SKIP  $($r.File)"; continue }
    $h = (Get-FileHash $p -Algorithm SHA256).Hash
    "{0,-6} {1}  {2}" -f $(if ($h -eq $r.SHA256) { 'OK' } else { 'DIFF' }), $r.File, $h.Substring(0,16)
}
"=== 2. ACL 复核（应全部干净）==="
foreach ($p in @($Root) + @($map.Values)) {
    if (-not (Test-Path $p)) { continue }
    $acl = (icacls "$p" 2>&1 | Out-String)
    "{0,-22} {1}" -f (Split-Path $p -Leaf), $(if ($acl -match 'DENY') { '仍有 DENY' } else { '干净' })
}
"=== 3. 任务复核 ==="
Get-ScheduledTask -TaskName "WpsUpdateTask_$env:USERNAME","WpsUpdateLogonTask_$env:USERNAME" -TaskPath '\' -ErrorAction SilentlyContinue |
    Select-Object TaskName, State
"=== 4. 服务复核 ==="
sc.exe qc wpscloudsvr | Select-String 'START_TYPE'
"=== 5. 行为复核：原版启动器应能正常开 WPS ==="
Start-Process -FilePath "$Root\ksolaunch.exe" -ArgumentList '/prometheus /from=startmenu'
Start-Sleep 12
"进程数: " + @(Get-Process wps,wpsoffice -ErrorAction SilentlyContinue).Count
```

**做什么**：五个维度一次性核对 —— 哈希、ACL、任务、服务、行为。
**预期输出**：

```text
=== 1. 哈希复核 ===
OK     root-ksolaunch.exe  6A1E302155B25504
OK     office6-ksolaunch.exe  6A1E302155B25504
OK     wtoolex-wpsupdate.exe  9F2C…
OK     wtoolex-updateself.exe  3B71…
OK     wtoolex-updatepolicy.exe  C40A…
=== 2. ACL 复核（应全部干净）===
WPS Office             干净
ksolaunch.exe          干净
ksolaunch.exe          干净
wpsupdate.exe          干净
updateself.exe         干净
updatepolicy.exe       干净
=== 3. 任务复核 ===
WpsUpdateTask_YEHY       Ready
WpsUpdateLogonTask_YEHY  Ready
=== 4. 服务复核 ===
        START_TYPE         : 3   DEMAND_START
=== 5. 行为复核 ===
进程数: 4
```

**失败怎么办**：
- 任一 `DIFF` → 用 `wps-backup\files\` 里的原件覆盖回去（9.2 最后一段有命令）。
- 仍有 DENY → 回 9.1。
- 任务缺失 → 回 9.3，必要时管理员窗口执行。
- 行为复核进程数 0 → 原版启动器本身有问题，用 `wps.exe` 的修复安装兜底。

**最后一步：把守卫壳日志留档（它是这次操作的证据，别急着删）**

```powershell
Copy-Item "$env:LOCALAPPDATA\Kingsoft\wps-guard.log" "$env:USERPROFILE\Desktop\wps-backup\wps-guard.log.final" -Force -ErrorAction SilentlyContinue
Get-Item "$env:USERPROFILE\Desktop\wps-backup\wps-guard.log.final" | Select-Object Name, Length, LastWriteTime
```

**做什么**：把守卫壳日志复制进备份目录存档，之后 WPS 自己会继续写新日志，但历史证据留住。
**预期输出**：`wps-guard.log.final`，大小数 KB。
**失败怎么办**：日志不存在（守卫壳从未被调用过）→ 忽略。

### 10.1 总表（先按现象定位到行，再按 10.2 起的小节修）

### 10.2 图标变成默认程序图标

**诊断**

```powershell
$ico = "$env:USERPROFILE\Desktop\wps-guard-build\src\wps.ico"
"ICO 是否存在: " + (Test-Path $ico)
if (Test-Path $ico) { "ICO 大小: " + (Get-Item $ico).Length + " bytes" }
$shim = "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.exe"
$real = "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.real.exe"
# 判定 1（首选）：原始文件名，与体积无关
"壳的 OriginalFilename  : " + (Get-Item $shim).VersionInfo.OriginalFilename
if (Test-Path $real) { "原版 OriginalFilename: " + (Get-Item $real).VersionInfo.OriginalFilename }
# 判定 2：两个文件哈希相同 = 已被换回原版；不同 = 守卫壳在位
if (Test-Path $real) {
    $h1 = (Get-FileHash $shim -Algorithm SHA256).Hash
    $h2 = (Get-FileHash $real -Algorithm SHA256).Hash
    "哈希比对: " + $(if ($h1 -eq $h2) { '相同 → 已被换回原版' } else { '不同 → 守卫壳在位' })
}
# 判定 3：exe 内是否带图标资源（只回答“图标在不在”，不回答“壳在不在”）
Add-Type -AssemblyName System.Drawing
$i = [System.Drawing.Icon]::ExtractAssociatedIcon($shim)
"提取到的图标: " + $i.Width + "x" + $i.Height
```

**做什么**：确认 ico 存在、壳是否在位（看 `OriginalFilename` 与新旧哈希，**不看体积**）、壳内是否带图标资源。
**预期输出**：

```text
ICO 是否存在: True
ICO 大小: 132… bytes
壳的 OriginalFilename  : ksolaunch.guard.exe
原版 OriginalFilename: ksolaunch.exe
哈希比对: 不同 → 守卫壳在位
提取到的图标: 32x32
```

**修复**：重编译（务必带 `/win32icon`）→ 解锁 → 覆盖落位 → 刷新缓存。

```powershell

icacls "$Root" /remove:d "$U"; icacls "$Root\ksolaunch.exe" /remove:d "$U"
Copy-Item "$env:USERPROFILE\Desktop\wps-guard-build\ksolaunch.guard.exe" "$Root\ksolaunch.exe" -Force
icacls "$Root\ksolaunch.exe" /deny "${U}:(WD,AD,WEA,WA,DE)"
icacls "$Root" /deny "${U}:(WD,AD)"
ie4uinit.exe -show
Stop-Process -Name explorer -Force
```

**失败怎么办**：`OriginalFilename` 是 `ksolaunch.guard.exe`、图标也能提取，但显示仍是白纸 → 问题在快捷方式缓存，删掉重钉一个：右键快捷方式 → 属性 → 更改图标 → 浏览到 `%LOCALAPPDATA%\Kingsoft\WPS Office\ksolaunch.exe` → 确定。

### 10.3 点图标没反应

**第一步：看日志（这是最快的定位方式）**

```powershell
Get-Content "$env:LOCALAPPDATA\Kingsoft\wps-guard.log" -Tail 10
```

- 有 `BLOCKED args=[/prometheus /fromksolaunch /from=startmenu]` → **事故一复现**：黑名单里混进了 `prometheus`。见下方修复。
- 有 `NO-TARGET` → 门户路径没找到（版本目录结构不同）。
- 有 `FAIL … err=` → 主程序起不来，按 `err` 原文定位（常见是安全软件拦截）。
- **完全没有新行** → 壳没被调用：快捷方式目标还指着别处，或壳根本不在位。

**第二步：确认壳在位且在跑**

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
Get-ChildItem $Root -Filter 'ksolaunch*' | Select-Object Name, Length
$shim = "$Root\ksolaunch.exe"
$p = Start-Process $shim -ArgumentList '/prometheus /fromksolaunch /from=startmenu' -PassThru
Start-Sleep 3
"退出码: " + $p.ExitCode + "  已退出: " + $p.HasExited
```

**做什么**：直接手工跑一次，绕过快捷方式，判断是壳的问题还是快捷方式的问题。
**预期输出**：`已退出: True`，同时 `wps-guard.log` 新增一行 `LAUNCH …`。
**失败怎么办**：手工跑有日志、点图标没有 → 快捷方式坏了，重建：右键 → 新建快捷方式 → 目标填 `"%LOCALAPPDATA%\Kingsoft\WPS Office\ksolaunch.exe" /prometheus /fromksolaunch /from=startmenu`。

**第三步：修复事故一（黑名单误含 prometheus）**

```powershell
$cs = "$env:USERPROFILE\Desktop\wps-guard-build\src\WpsLaunchGuard.cs"
Select-String -Path $cs -Pattern 'prometheus' -SimpleMatch
```

**做什么**：确认源码黑名单里有没有 `prometheus`。
**预期输出**：注释行可能命中（`// /prometheus 正常启动标志，曾被误拦`），但 `BlockedCores` 数组里**不应出现** `"prometheus"`。
**失败怎么办**：真出现了 → 删掉那一行 → 按 4.6 重编译 → 按 4.7 步骤 1～5 重落位 → 按 8.3 入口 1 复验。

### 10.4 任务栏图标不灵（事故二）

**诊断**

```powershell
Get-Content "$env:LOCALAPPDATA\Kingsoft\wps-guard.log" -Tail 20 | Select-String 'taskbar'
```

**做什么**：看任务栏调用是否被记成 `BLOCKED`。
**预期输出**：应出现 `LAUNCH args=[/prometheus /fromksolaunch /from=taskbar]`。
**失败怎么办**：出现 `BLOCKED … from=taskbar` → 匹配方式退化成子串了。检查源码：

```powershell
$cs = "$env:USERPROFILE\Desktop\wps-guard-build\src\WpsLaunchGuard.cs"

```

**做什么**：确认 `IsBlocked` 里是 `core == b`（全等），而不是 `core.Contains(b)`。
**预期输出**：

```text
9:    private static bool IsBlocked(string argsJoined)
31:                if (core == b) return true;
```

**失败怎么办**：看到 `core.Contains(b)` → 改成 `core == b` → 重编译 → 重落位（第 4 章步骤 1～5）→ 用 8.3 入口 3 复验。

### 10.5 自动更新失效

**先说清楚**：这是**设计目标**，不是故障。验收标准就是「版本长期不动、`wpsupdate_*.log` 不再增长」。

**若你确实想恢复更新能力**（例如要升级新版本），按这个顺序放开：

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"; $U = "$env:USERDOMAIN\$env:USERNAME"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName
foreach ($f in @("$Ver\office6\ksolaunch.exe","$Ver\wtoolex\wpsupdate.exe","$Ver\wtoolex\updateself.exe","$Ver\wtoolex\updatepolicy.exe")) {
    if (Test-Path $f) { icacls "$f" /remove:d "$U"; "已解锁: $(Split-Path $f -Leaf)" }
}
icacls "$Root" /remove:d "$U"; "已解锁目录: $Root"
```

**做什么**：撤掉 4 个载荷与安装根目录的 DENY，更新链路恢复。
**预期输出**：5 行 `已解锁: …`
**失败怎么办**：想让更新彻底恢复原样，还要按 9.3 重建任务、按 9.4 恢复服务。

**只想临时放行、升级完再锁回去**：

```powershell
# 升级完（或重装后）重新执行第 5 章 5.4 的 6 条命令即可，无需重编守卫壳
```

### 10.6 重装/升级后失效

**症状**：重装 WPS、或大版本升级（如 12.1.0.29690 → 12.1.0.30100）之后，开机又自动起来，任务也回来了。

**原因**（三条同时发生）：
1. 安装器释放了**新的版本目录**，新目录里的 `wpsupdate.exe` 没被 ACL 覆盖；
2. 安装器把安装根目录的 ACL 重置为出厂继承状态，旧 DENY 全部失效；
3. 安装器按设计执行 `wps.exe /prometheus /from=autostart_after_install`，并注册两条计划任务。

**处置**：按顺序重做，**不需要重新提取图标**（除非图标也变了）。

```powershell
"=== 1. 确认新版本目录 ==="
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Select-Object Name, LastWriteTime
"=== 2. 确认守卫壳是否还在、哈希是否变了 ==="
Get-ChildItem $Root -Filter 'ksolaunch*' | Select-Object Name, Length, LastWriteTime
"=== 3. 确认 DENY 是否被打回原形 ==="
foreach ($p in @("$Root", "$Root\ksolaunch.exe")) { "--- $p"; icacls "$p" }
```

**做什么**：三步确认「变了什么」。
**预期输出**：出现一个新的版本目录；ACL 输出里**没有** `(DENY)` 字样（被重置了）。
**失败怎么办**：
- 守卫壳被新版本覆盖回原版 → 按 4.7 重做替换（图标已经生成过，直接编译即可）。
- 图标文件 `wps.ico` 丢了 → 按 4.4 重新提取（源用 `office6\wpsoffice.exe`，此时根 `ksolaunch.exe` 已是原版也行）。
- 新版本没有 `wtoolex` → 第 5 章只锁 `office6\ksolaunch.exe` 与目录。

**重做清单（打印出来逐项勾）**

| 序 | 动作 | 章节 |
|---|---|---|
| 1 | 重做备份（新版本目录的原件与新哈希） | 3.3 |
| 2 | 重新编译守卫壳并落位 | 4.6 / 4.7 |
| 3 | 对新版本目录的 4 个载荷重下 DENY | 5.4 |
| 4 | 重新禁用+删除两条任务 | 6.2 / 6.3 |
| 5 | 服务再禁用一次（安装器会改回自动） | 7.2 |
| 6 | 总验 | 8.5 |

### 10.7 安全模式进不去

**症状**：开机按 F8 或用 `msconfig` 勾了「安全启动」后，系统反复进启动修复，进不了安全模式。

**原因**：`bcdedit` 里残留了 `safeboot` 引导标志（常见于调试、杀软救援、或手工改过引导项）。这与 WPS 无关，但经常被一起问到，一并写在这里。

**诊断**

```cmd
bcdedit /enum {current}
```

**做什么**：打印当前引导项的全部设置。
**预期输出**：正常系统里**不应出现** `safeboot` 行。
**失败怎么办**：看到 `safeboot Minimal` 或 `safeboot Network` 之类的行 → 执行下面这条清掉。

**修复**

```cmd
bcdedit /deletevalue {current} safeboot
```

**做什么**：删除 `{current}` 引导项上的 `safeboot` 标志，恢复正常启动。
**预期输出**：

```text
操作成功完成。
```

**失败怎么办**：
- `指定的元素未找到` → 本来就没有该标志，问题不在引导项，转查启动修复日志 `C:\Windows\System32\LogFiles\Srt\SrtTrail.txt`。
- `Access is denied`（权限不足） → 必须以管理员运行 `cmd`。提权方式：开始菜单 → 输入 `cmd` → 右键「以管理员身份运行」。
- 提示找不到 `{current}` → 用 `bcdedit /enum all` 找到真实标识符（形如 `{1a2b3c4d-…}`），把命令里的 `{current}` 换成它。
- 清完仍进不了安全模式 → 检查 `msconfig` 的「引导」页是否还有「安全启动」勾选，取消后重启。

**同时清掉「安全启动最小化」附带项（如有）**

```cmd
bcdedit /deletevalue {current} safebootalternateshell
```

**做什么**：清掉安全模式的备用外壳标志（同样是安全模式的附属项）。
**预期输出**：`操作成功完成。` 或 `指定的元素未找到`（都正常）。
**失败怎么办**：报「元素未找到」即无需处理。

### 10.8 其他常见现象

| 现象 | 检查 | 处置 |
|---|---|---|
| 右键「用 WPS 打开」没反应 | 文件关联指向 `office6\ksolaunch.exe`（已禁执行） | 设置 → 应用 → 默认应用 → 按文件类型改到 `office6\wpsoffice.exe` |

## 11 适用范围与限制

### 11.1 用户级安装（`%LOCALAPPDATA%`）—— 本手册的主场

| 项目 | 情况 |
|---|---|
| 典型路径 | `C:\Users\<用户>\AppData\Local\Kingsoft\WPS Office` |
| 闸3（ACL） | **普通权限即可**，因为文件属主就是当前用户 |
| 闸4（换壳） | **普通权限即可** |
| 闸1（计划任务） | 禁用多数情况普通权限可做；**删除遇到 `Access is denied` 时需管理员** |
| 闸2（服务） | **必须管理员** |
| 生效范围 | 只对当前用户生效。同一台机器的其他账户要各自做一遍（ACL 是按 SID 的，但我们下 DENY 时用的是当前账户） |

**验证属于哪种安装**：

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
if (Test-Path $Root) { "用户级安装：$Root" } else { "用户级安装不存在，检查 Program Files"; Get-ChildItem "$env:ProgramFiles\Kingsoft","${env:ProgramFiles(x86)}\Kingsoft" -ErrorAction SilentlyContinue } 
```

**做什么**：一步判断是用户级还是全局。
**预期输出**：`用户级安装：C:\Users\YEHY\AppData\Local\Kingsoft\WPS Office`
**失败怎么办**：输出落到 `Program Files` 分支 → 按 11.2 处理。

### 11.2 全局安装（`Program Files`）—— 必须管理员，且部分闸门失效

| 项目 | 情况 |
|---|---|
| 典型路径 | `C:\Program Files\Kingsoft\WPS Office` 或 `C:\Program Files (x86)\Kingsoft\WPS Office` |
| 闸3（ACL） | **每条 `icacls` 都要管理员**；且 DENY 的对象应写成 `Users` 或具体账户全名，不要只写自己（否则换账户照样自启） |
| 闸4（换壳） | **必须管理员**，因为 `Program Files` 的写权限只给 TrustedInstaller / Administrators |
| 闸1（计划任务） | 必须管理员 |
| 闸2（服务） | 必须管理员 |
| 副作用 | 全局安装的更新由 SYSTEM 身份执行，SYSTEM 不受用户级 DENY 约束 —— **闸3 对全局安装的拦阻效果明显弱于用户级**。全局安装场景下，闸4（换壳）+ 闸1（删任务）是主力 |

**全局安装的两处命令替换（其余照旧）**：

```cmd
:: 把 %LOCALAPPDATA%\Kingsoft\WPS Office 换成实际安装根
set "WPSROOT=C:\Program Files\Kingsoft\WPS Office"
icacls "%WPSROOT%\office6\ksolaunch.exe" /deny "Users:(X,WD,AD,WEA,WA,DE)"
icacls "%WPSROOT%\wtoolex\wpsupdate.exe" /deny "Users:(X,WD,AD,WEA,WA,DE)"
icacls "%WPSROOT%" /deny "Users:(WD,AD)"
```

**做什么**：把 DENY 对象从「当前用户」换成内置 `Users` 组，覆盖所有普通账户。
**预期输出**：每条 `已处理 1 个文件。`
**失败怎么办**：`Access is denied`（权限不足） → 确认 cmd 是管理员窗口（标题带「管理员」）。`Users` 组名在非中文系统上是 `Users`，本机化系统上也可写成 `BUILTIN\Users`。

### 11.3 不同 WPS 版本的目录差异

| 差异点 | 表现 | 手册中的应对 |
|---|---|---|
| 没有 `wtoolex` 目录 | 第 5 章命令 2、3、4 报 `已处理 0 个文件` | 跳过三条命令，只锁 `office6\ksolaunch.exe` 与目录；第 8 章参数 B、C 仍可验证（壳会拦） |
| 没有根级 `ksolaunch.exe` | `%LOCALAPPDATA%\Kingsoft\WPS Office` 下只有版本目录 | 第 4 章整章跳过；图标直接指向版本目录，闸3 会把图标一起废掉 —— 此时只做闸3 的**除执行外**部分：`(WD,AD,WEA,WA,DE)` |
| 主程序叫 `wps.exe` 而不是 `wpsoffice.exe` | 守卫壳报 `NO-TARGET` | 源码已经内置回退：先找 `wpsoffice.exe`，再找 `wps.exe`，最后回退 `ksolaunch.real.exe`。三者都没有才 `NO-TARGET` |
| 版本目录名不是纯数字点分（如 `12.1.0.29690_zh`） | 正则 `^\d+(\.\d+)+$` 匹配不上 | 改正则或直接硬编码版本目录；改完重编译 |
| 多个版本目录共存 | 旧版本仍在被任务引用 | 对**每一个**版本目录都执行第 5 章 5.4；守卫壳默认开版本号最大的一个 |
| 服务名不是 `wpscloudsvr` | `sc qc` 报 1060 | 用 `Get-Service | Where-Object { $_.Name -match 'wps|kingsoft' }` 找真实服务名，替换第 7 章命令里的名字 |

**多版本共存的批量上锁（把第 5 章 5.4 循环化）**

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"; $U = "$env:USERDOMAIN\$env:USERNAME"
Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | ForEach-Object {
    $v = $_.FullName
    foreach ($rel in @('office6\ksolaunch.exe','wtoolex\wpsupdate.exe','wtoolex\updateself.exe','wtoolex\updatepolicy.exe')) {
        $f = Join-Path $v $rel
        if (Test-Path $f) { icacls "$f" /deny "${U}:(X,WD,AD,WEA,WA,DE)" | Out-Null; "已锁: $rel  @ $($_.Name)" }
    }
}
icacls "$Root" /deny "${U}:(WD,AD)" | Out-Null
"安装根已锁"
```

**做什么**：对所有版本目录批量下同一套 DENY。
**预期输出**：每个版本 3～4 行 `已锁: …`，最后 `安装根已锁`。
**失败怎么办**：报 `Access is denied`（权限不足） → 该版本目录属主是 TrustedInstaller（典型于升级残留），需要管理员窗口。

### 11.4 什么情况会把这套方案打回原形（必须知道）

| 触发事件 | 被打回的部分 | 重做范围 |
|---|---|---|
| WPS 重装 | ACL 重置、任务重建、守卫壳被覆盖 | 第 4、5、6、7 章 |
| WPS 大版本升级（版本目录变化） | 新目录无 DENY；旧目录的锁变成无效锁 | 第 5 章 + 守卫壳重编译（源码不用改） |
| 系统还原点恢复 | 注册表与 ACL 一起回滚 | 第 4、5、6、7 章 |
| 用第三方「优化大师」类工具重置权限 | ACL 被清 | 第 5 章 |
| 磁盘迁移/更换用户配置文件 | SID 变化，原 DENY 里的账户名对不上 | 全部重来 |
| 手动执行第 9 章回退 | 全部恢复 | —— |

**每次开机后的体检脚本（30 秒）**

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName
$shim = "$Root\ksolaunch.exe"; $real = "$Root\ksolaunch.real.exe"

# 1) 壳是否在位：只看原始文件名 + 两文件哈希，不看体积
$ofn = (Get-Item $shim).VersionInfo.OriginalFilename
if (-not (Test-Path $real)) {
    "1) 守卫壳: 无原版存档（尚未替换，或已执行回退）"
} elseif ((Get-FileHash $shim -Algorithm SHA256).Hash -eq (Get-FileHash $real -Algorithm SHA256).Hash) {
    "1) 守卫壳: 已被换回原版（两文件哈希相同）"
} else {
    "1) 守卫壳: 在位（OriginalFilename=$ofn，与 ksolaunch.real.exe 哈希不同）"
}

# 2) 原版存档是否还在
"2) 原版存档: " + $(if (Test-Path $real) { '存在' } else { '缺失' })

# 3) 载荷封锁：行为判定（能执行 = 没锁住），不解析 icacls 文本
$locked = 0; $runnable = 0
foreach ($f in @("$Ver\office6\ksolaunch.exe","$Ver\wtoolex\wpsupdate.exe","$Ver\wtoolex\updateself.exe","$Ver\wtoolex\updatepolicy.exe")) {
    if (-not (Test-Path $f)) { continue }
    try { $p = Start-Process -FilePath $f -ArgumentList '-createtask' -PassThru -ErrorAction Stop; try { $p.Kill() } catch {}; $runnable++ }
    catch { $locked++ }
}
"3) 载荷封锁: $locked 拦下 / $runnable 仍可执行"

# 4) 任务残留
"4) 任务残留: " + @(Get-ScheduledTask | Where-Object { ($_.Actions | ForEach-Object { "$($_.Execute) $($_.Arguments)" }) -join ' ' -match 'ksolaunch|wpsupdate' }).Count

# 5) 服务
"5) 服务: " + (sc.exe qc wpscloudsvr 2>&1 | Select-String 'START_TYPE')

# 6) 目录新建探针（测完自行删除）
$probe = "$Root\_probe_$([guid]::NewGuid().ToString('N').Substring(0,4))"
try { New-Item -ItemType Directory -Path $probe -ErrorAction Stop | Out-Null; Remove-Item $probe -Force; $dirLocked = $false } catch { $dirLocked = $true }
"6) 目录新建: " + $(if ($dirLocked) { '被拦（正常）' } else { '仍可新建（未锁住）' })
```

**做什么**：六项指标一眼看完 —— 壳是否在位（文件名 + 哈希，不看体积）、原版是否存档、4 个载荷是否被锁（行为判定）、任务是否残留、服务状态、目录是否锁住。
**预期输出**（本机实测原文）：

```text
1) 守卫壳: 在位（OriginalFilename=ksolaunch.guard.exe，与 ksolaunch.real.exe 哈希不同）
2) 原版存档: 存在
3) 载荷封锁: 4 拦下 / 0 仍可执行
4) 任务残留: 0
5) 服务:         START_TYPE         : 4   DISABLED
6) 目录新建: 被拦（正常）
```

**失败怎么办**：任一项偏离 → 按上表「重做范围」补做对应章节。指标 3 出现「仍可执行」最常见（升级后新增文件没被覆盖），回第 5 章 5.4 补锁即可；指标 1 显示「已被换回原版」→ 回 4.6 重编译、4.7 重落位。

## 12 闸5 升级通道（禁用 WPS 升级）

> 逻辑上这是第五道闸。位置排在最后，是为了不打乱前面章节已有的交叉引用（5.4 / 5.6 / 8.3 / 9.1 / 11.4 等），编号只做递增。
> 本章全部操作走 `HKCU`，**用户级安装普通权限即可**；只有 12.4 的两个可选加固需要管理员。

### 12.1 原理：升级检测只有三步

**第 1 步 读服务器地址。** `wpsupdate.exe` 启动时先从注册表读三处地址。实机读到的原值：

```text
HKCU\SOFTWARE\Kingsoft\Office\6.0\Common
  UpdateSvr    = http://update.wps.cn/updateserver/update;http://update2.wps.cn/updateserver/update
  UpdateSecSvr = https://update.wps.cn/updateserver/update;https://update2.wps.cn/updateserver/update
  NotifySvr    = http://notify.wps.cn/notifyserver/notify
```

关键细节：`UpdateSvr` 与 `UpdateSecSvr` 是**分号分隔的多地址**，第一条连不上会顺次走第二条。这就是「只改第一条仍然会升级」的原因。

**第 2 步 POST 版本清单。** 更新器向该地址 POST 一个 XML，携带本机的 `version` / `productid` / `buildid` 等信息。

**第 3 步 比较后提示。** 服务器回版本清单 → 更新器与本机版本比对 → 有新版本才弹「发现新版本」。

**闸5 打的是第 2 步**：地址改成本机 discard 端口后，TCP 连接在建立阶段就被对端用 RST 重置，XML 发不出去，版本清单拿不到，第 3 步失去比较对象。整个升级链路在这里断开，且**不产生任何外网流量**。

**二进制取证**（证明这三个值确实是运行期读取，不是死配置）：
把 `wpsupdate.exe`、`updateself.exe`、`updatepolicy.exe` 的字节按 UTF-16 与 ASCII 双解码扫字符串，命中如下：

| 值名 | 命中文件 |
|---|---|
| `UpdateSvr` | `wpsupdate.exe`、`updateself.exe` |
| `UpdateSecSvr` | `wpsupdate.exe`、`updateself.exe` |
| `NotifySvr` | `wpsupdate.exe`、`updateself.exe` |
| `updateinfo` | `wpsupdate.exe`、`updateself.exe`、`updatepolicy.exe` |
| `LastCheckTime` | `wpsupdate.exe`、`updateself.exe` |

值名出现在可执行文件里 = 运行时按名取值 → 改值即断源。

**各道闸对升级的作用对照**（互不替代，叠起来才稳）：

| 闸 | 拦在哪 | 升级仍能走通的条件 |
|---|---|---|
| 闸3 文件 ACL | `wpsupdate.exe` 起不来 | 升级换了新版本目录、新文件未被 ACL 覆盖 |
| 闸4 守卫壳 | `-createtask` / `-repairtask` / 自启参数被丢弃 | 走 WPS 主界面「检查更新」菜单 |
| 闸5 注册表地址 | 更新器能跑，但连不上版本服务器 | 值被恢复或被重装重置 |
| 闸1 / 闸2 | 计划任务与服务 | 与升级检测本身无关 |

### 12.2 备份三个原值（分号多地址必须整条记）

> **要点**：备份必须保存**整条字符串**（含分号与第二条地址）。只记第一条等于没备份——回退后仍会走备用域名。

> **⚠ 重复备份的陷阱（必读）**：写备份的命令用的是**固定文件名** `wps-update-svr-original.json`，重复执行会把它覆盖。
> 如果你在**已经改过**（或已经被禁用）的状态下再跑一次备份，读到的"原值"就是 `127.0.0.1:9`，覆盖后**真正的原始地址就没了**，之后再恢复只会把黑洞地址写回去。
> 所以：**备份只在动手改之前做一次**。要重新备份，先把旧文件改名带时间戳（`Move-Item ... wps-update-svr-original.<时间>.json`），或者直接检查当前三个值里有没有 `127.0.0.1` —— 有就说明当前不是干净状态，先恢复再备份。

#### 方式 A：结构化快照（推荐）

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"
New-Item -ItemType Directory -Force "$B\reg" | Out-Null
$K = 'HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common'
$key = Get-Item $K

$snap = foreach ($n in 'UpdateSvr','UpdateSecSvr','NotifySvr') {
    $v = Get-ItemPropertyValue -Path $K -Name $n -ErrorAction SilentlyContinue
    if ($null -eq $v) { [pscustomobject]@{ Name = $n; Exists = $false; Kind = ''; Value = '' } }
    else { [pscustomobject]@{ Name = $n; Exists = $true; Kind = $key.GetValueKind($n).ToString(); Value = $v } }
}
$snap | Format-List
$snap | ConvertTo-Json -Depth 3 | Set-Content "$B\reg\wps-update-svr-original.json" -Encoding UTF8
"已保存: $B\reg\wps-update-svr-original.json"
```

**做什么**：把三个值连同**值类型（Kind）**与存在性一起存成 JSON。记 Kind 是因为回退时要按原类型写回（`REG_SZ` 与 `REG_EXPAND_SZ` 混写会改变行为）。
**预期输出**：

```text
Name        : UpdateSvr
Exists      : True
Kind        : String
Value       : http://update.wps.cn/updateserver/update;http://update2.wps.cn/updateserver/update

Name        : UpdateSecSvr
Exists      : True
Kind        : String
Value       : https://update.wps.cn/updateserver/update;https://update2.wps.cn/updateserver/update

Name        : NotifySvr
Exists      : True
Kind        : String
Value       : http://notify.wps.cn/notifyserver/notify

已保存: C:\Users\YEHY\Desktop\wps-backup\reg\wps-update-svr-original.json
```

**失败怎么办**：
- 某项 `Exists : False` → 该版本没有这个值（见 12.7），照常记录，实施阶段自动跳过它。
- `Set-Content` 报权限不足 → 备份目录被闸3 的目录 DENY 波及，把 `$B` 换到桌面之外的固定盘，如 `C:\wps-backup`。

#### 方式 B：整键导出（交叉验证用）

```cmd
reg export "HKCU\SOFTWARE\Kingsoft\Office\6.0\Common" "%USERPROFILE%\Desktop\wps-backup\reg\common.reg" /y
```

**做什么**：把整个 `Common` 键导成 .reg，作为方式 A 的对照与紧急恢复手段。
**预期输出**：`操作成功完成。`
**失败怎么办**：`错误: 系统找不到指定的注册表项或值。` → 该账户从未跑过 WPS，启动一次 WPS 生成键后再导出。

#### 备份自查（两件事都要过）

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"
$o = Get-Content "$B\reg\wps-update-svr-original.json" -Raw | ConvertFrom-Json
$o | Select-Object Name, Exists, Kind
"UpdateSvr 拆分条数: " + ((($o | Where-Object Name -eq 'UpdateSvr').Value -split ';') -join ' / ')
```

**做什么**：回读 JSON，并确认 `UpdateSvr` 按分号能拆出多条地址。
**预期输出**：

```text
Name         Exists Kind
----         ------ ----
UpdateSvr      True String
UpdateSecSvr   True String
NotifySvr      True String
UpdateSvr 拆分条数: http://update.wps.cn/updateserver/update / http://update2.wps.cn/updateserver/update
```

**失败怎么办**：拆分只出 1 条 → 备份时被截断过，重跑方式 A；拆分出 3 条以上 → 原值里有多余分号，照原样保存即可，恢复时整条写回。

### 12.3 实施：三个值改写为 127.0.0.1:9

```powershell
$K = 'HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common'
$map = [ordered]@{
    UpdateSvr    = 'http://127.0.0.1:9/updateserver/update'
    UpdateSecSvr = 'https://127.0.0.1:9/updateserver/update'
    NotifySvr    = 'http://127.0.0.1:9/notifyserver/notify'
}
$key = Get-Item $K
foreach ($k in $map.Keys) {
    $old = Get-ItemPropertyValue -Path $K -Name $k -ErrorAction SilentlyContinue
    if ($null -eq $old) { "SKIP  值不存在，跳过（不创建新值）: $k"; continue }
    $kind = $key.GetValueKind($k).ToString()      # 保留原值类型，按原类型写回
    Set-ItemProperty -Path $K -Name $k -Value $map[$k] -Type $kind
    "改写: {0}  [{1}]`n  旧: {2}`n  新: {3}" -f $k, $kind, $old, (Get-ItemPropertyValue -Path $K -Name $k)
}
```

**做什么**：逐值「先读旧值 → 存在才写 → 写完回读打印」。值不存在时跳过，不凭空造值。
**预期输出**：

```text
改写: UpdateSvr
  旧: http://update.wps.cn/updateserver/update;http://update2.wps.cn/updateserver/update
  新: http://127.0.0.1:9/updateserver/update
改写: UpdateSecSvr
  旧: https://update.wps.cn/updateserver/update;https://update2.wps.cn/updateserver/update
  新: https://127.0.0.1:9/updateserver/update
改写: NotifySvr
  旧: http://notify.wps.cn/notifyserver/notify
  新: http://127.0.0.1:9/notifyserver/notify
```

**失败怎么办**：
- `Set-ItemProperty` 报权限不足 → `Common` 键的 ACL 被改过（少见）。用 `reg add` 以管理员身份重试：`reg add "HKCU\SOFTWARE\Kingsoft\Office\6.0\Common" /v UpdateSvr /t REG_SZ /d "http://127.0.0.1:9/updateserver/update" /f`。
- 全部 `SKIP` → 键路径不对。先跑 12.7 的探测命令确认真实键路径与值名。
- 写完回读还是旧值 → WPS 托盘进程持有缓存，退出托盘图标后再写一次。

#### 为什么必须是「127.0.0.1 + 端口 9」

| 改法 | 更新器拿到什么 | 用户感知 |
|---|---|---|
| `http://127.0.0.1:9/...`（本手册） | 连接立即被 RST 重置，毫秒级失败 | 无感，无卡顿 |
| 不存在的域名 `http://update.invalid/...` | 先 DNS 解析，等到解析超时才失败 | 每次检查更新卡 5～15 秒 |
| 黑洞 IP `http://10.255.255.1/...` | TCP SYN 无响应，等连接超时并重试 | 卡 20 秒以上，明显 |
| 直接删值 | 更新器回落到内置默认地址 | 照常升级，等于没做 |

端口 **9** 是 TCP/UDP 的 discard 服务端口，Windows 本机默认没有进程监听。发往它的 SYN 会被内核直接回 **RST**，所以「失败」发生在毫秒级，而不是超时级。加上 `127.0.0.1` 是回环地址，任何尝试都不经过网卡，**零外网流量**，也不会触发任何外联类告警。

**端口 9 是否真的没人监听（先验证再依赖）**

```powershell
try {
    $c = New-Object System.Net.Sockets.TcpClient
    $c.Connect('127.0.0.1', 9)
    "注意：端口 9 有进程在监听（Connected=$($c.Connected)），改用 127.0.0.1 之外的空闲端口"
    $c.Close()
} catch {
    "端口 9 连接被重置，符合预期"
}
```

**做什么**：主动连一次 `127.0.0.1:9`，确认失败是「被重置」而不是「被接受」。
**预期输出**：`端口 9 连接被重置，符合预期`
**失败怎么办**：真的有人监听 → 换一个确定空闲的高位端口（如 1），把 12.3 三个值和本节说明里的 `:9` 全部同步替换，保持三处一致。

### 12.4 可选加固（需要管理员）

> 12.3 已经断开升级链。12.4 是双保险：万一某次升级把注册表值重建回官方地址，hosts 与防火墙仍然拦得住。不做也能正常工作。

#### 12.4.1 hosts 封域名

hosts 文件路径（固定）：`%SystemRoot%\System32\drivers\etc\hosts`，本机即 `C:\Windows\System32\drivers\etc\hosts`。它归 SYSTEM 所有，**写入需要管理员**。

```powershell
$h = "$env:SystemRoot\System32\drivers\etc\hosts"
$bak = "$h.wps-before"
$mark = '# WPS update block'

# 只在第一次留一份干净备份，重复执行不会覆盖成"已污染"的版本
if (-not (Test-Path $bak)) { Copy-Item $h $bak -Force; "已备份到 $bak" } else { "备份已存在：$bak（不覆盖）" }

# 幂等：已经有标记段就不再追加，避免重复行越叠越多
if (Select-String -Path $h -Pattern ([regex]::Escape($mark)) -Quiet) {
    "已存在 $mark 段，跳过追加"
} else {
    Add-Content -Path $h -Value "`r`n$mark`r`n127.0.0.1 update.wps.cn update2.wps.cn notify.wps.cn" -Encoding ASCII
    "已追加 $mark 段"
}
Get-Content $h -Tail 4
ipconfig /flushdns
```

**做什么**：先备份 hosts → 追加一行把三个升级域名解析到本机 → 回读确认 → 刷新 DNS 缓存。
**预期输出**：

```text
# WPS update block
127.0.0.1 update.wps.cn update2.wps.cn notify.wps.cn

Windows IP 配置

已成功刷新 DNS 解析缓存。
```

**失败怎么办**：
- `Add-Content` 报权限不足 → 用管理员 PowerShell 重跑（开始菜单搜 PowerShell → 右键「以管理员身份运行」）。
- 刷新后仍解析到公网 IP → 浏览器/系统 DoH 生效，改用 12.4.2 的防火墙规则。
- 想撤回：`Remove-Item $h -Force; Copy-Item "$h.bak-时间戳" $h`，或手工删掉那两行。

#### 12.4.2 防火墙按程序封锁出站

```cmd
netsh advfirewall firewall add rule name="WPS Update Block" dir=out program="%LOCALAPPDATA%\Kingsoft\WPS Office\12.1.0.29690\wtoolex\wpsupdate.exe" action=block enable=yes
netsh advfirewall firewall add rule name="WPS Update Block self" dir=out program="%LOCALAPPDATA%\Kingsoft\WPS Office\12.1.0.29690\wtoolex\updateself.exe" action=block enable=yes
netsh advfirewall firewall add rule name="WPS Update Block policy" dir=out program="%LOCALAPPDATA%\Kingsoft\WPS Office\12.1.0.29690\wtoolex\updatepolicy.exe" action=block enable=yes
```

**做什么**：为三个更新器分别建一条出站阻止规则（只拦这三个程序，不影响 WPS 正文与云文档）。
**预期输出**：每条一行 `确定。`
**失败怎么办**：
- `发生错误: Access is denied`（中文系统显示「权限不足」） → 提到管理员；管理员窗口重跑。
- 版本目录变了 → 规则指向的路径失效。规则按**全路径**匹配，所以升级后要用下方的查看命令核对路径。

**查看与清理**

```cmd
netsh advfirewall firewall show rule name="WPS Update Block"
netsh advfirewall firewall delete rule name="WPS Update Block"
netsh advfirewall firewall delete rule name="WPS Update Block self"
netsh advfirewall firewall delete rule name="WPS Update Block policy"
```

**做什么**：先显示规则确认已生效（含程序路径与「操作: 阻止」），恢复时逐条删除。
**预期输出**：显示时出现 `操作:                             阻止` 与 `程序:  ...\wpsupdate.exe`；删除时每条 `已删除 … 规则。`
**失败怎么办**：`没有与指定标准相符的规则。` → 规则本来就没建（或名字拼错），跳过。

### 12.5 验证（四步，逐步给判据）

#### 第 1 步 注册表值已指向 127.0.0.1:9

```powershell
$K = 'HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common'
foreach ($n in 'UpdateSvr','UpdateSecSvr','NotifySvr') {
    $v = Get-ItemPropertyValue -Path $K -Name $n -ErrorAction SilentlyContinue
    "{0,-13} = {1}" -f $n, $(if ($null -eq $v) { '(值不存在)' } else { $v })
}
```

**做什么**：把三个值当前内容原样打印。
**预期输出**：

```text
UpdateSvr     = http://127.0.0.1:9/updateserver/update
UpdateSecSvr  = https://127.0.0.1:9/updateserver/update
NotifySvr     = http://127.0.0.1:9/notifyserver/notify
```

**失败怎么办**：还是 `update.wps.cn` → 12.3 没写进去（或 WPS 把它写回了），重跑 12.3 并退出 WPS 托盘进程后复查。

#### 第 2 步 更新器本体执行已被闸3 拦下

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName
$u    = "$Ver\wtoolex\wpsupdate.exe"
if (-not (Test-Path $u)) { "该版本无 wpsupdate.exe，跳过本步" }
else {
    try { $p = Start-Process -FilePath $u -ArgumentList '-checkupdate' -PassThru -ErrorAction Stop; "FAIL 仍可执行: $u"; try { $p.Kill() } catch {} }
    catch { "PASS 执行被拦下（闸3 生效）: $($_.Exception.Message)" }
}
```

**做什么**：直接拉更新器，确认 ACL DENY 仍在起作用。
**预期输出**：

```text
PASS 执行被拦下（闸3 生效）: ...Access is denied（中文系统显示「权限不足」）
```

中文系统的消息体通常是权限错误，关键是它**抛异常**。
**失败怎么办**：显示 `FAIL 仍可执行` → 闸3 的 ACL 掉了（升级/重装后常见），回 5.4 补锁 `wtoolex\wpsupdate.exe` 的 `(X,WD,AD,WEA,WA,DE)`。

#### 第 3 步 hosts 生效（仅在做了 12.4.1 时执行）

```powershell
try {
    $ips = [System.Net.Dns]::GetHostAddresses('update.wps.cn') | ForEach-Object { $_.IPAddressToString }
    "update.wps.cn -> " + ($ips -join ', ')
} catch { "解析失败（hosts 可能没生效）: $($_.Exception.Message)" }
```

**做什么**：解析升级域名，看落到哪里。
**预期输出**：`update.wps.cn -> 127.0.0.1`
**失败怎么办**：
- 解析出公网 IP → hosts 没写进或被 DoH 绕过。用 `Get-Content "$env:SystemRoot\System32\drivers\etc\hosts" -Tail 4` 确认末行在，然后 `ipconfig /flushdns` 再来一次。
- 解析失败 → hosts 里写成了错误格式（一行一个域名更稳）。

#### 第 4 步 状态位与日志（这里有个容易踩的坑）

```powershell
$p = 'HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common\updateinfo\cacheStatusInfo'
if (Test-Path $p) {
    "wpsUpdateStatus = " + (Get-ItemPropertyValue -Path $p -Name 'wpsUpdateStatus' -ErrorAction SilentlyContinue)
} else { "缓存项路径不存在（该版本无此项）" }
```

**必须先说清一件事：`wpsUpdateStatus = UpdateError` 不足以作为闸5 生效的证据。**

闸3 把 `wpsupdate.exe` 的执行权拿掉之后，更新器根本跑不起来，这个状态位会**一直是** `UpdateError`——闸5 改没改都一样。它是「闸3 生效」的痕迹，不是「闸5 生效」的痕迹。

**闸5 的正确验证有两条，任选一条就能判定：**

**判定 A（推荐，无需改动系统）：看更新器还会不会活动。**

改完闸5 之后正常用几次 WPS，然后查更新日志的最后写入时间：

```powershell
$logDir = "$env:APPDATA\kingsoft\office6\log\update"
Get-ChildItem $logDir -Filter 'wpsupdate_*.log' -ErrorAction SilentlyContinue |
    Sort-Object LastWriteTime -Descending | Select-Object -First 1 | ForEach-Object {
        "最新更新日志: " + $_.Name + "   最后写入: " + $_.LastWriteTime
    }
```

判据：闸3 + 闸5 都在位时，这个时间会**停在禁用那一刻不再前进**——更新器既跑不起来，也不需要跑。这是两者叠加后的正常形态。

**判定 B（解耦验证，能直接看到「连不上」）：临时放行更新器跑一次，看它连到哪儿。**

适合你想亲眼看一次「地址确实被指到了 127.0.0.1」。**做完必须复锁**：

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName
$u    = "$Ver\wtoolex\wpsupdate.exe"
$U    = "$env:USERDOMAIN\$env:USERNAME"
$logDir = "$env:APPDATA\kingsoft\office6\log\update"

# ① 临时解 DENY
icacls "$u" /remove:d "$U"

# ② 跑一次检查更新，给它 8 秒
$before = (Get-ChildItem $logDir -Filter 'wpsupdate_*.log' | Sort-Object LastWriteTime -Descending | Select-Object -First 1).Length
Start-Process -FilePath $u -ArgumentList '-checkupdate' -Wait -ErrorAction SilentlyContinue
Start-Sleep -Seconds 4

# ③ 看日志里这次连接的结果
Get-ChildItem $logDir -Filter 'wpsupdate_*.log' | Sort-Object LastWriteTime -Descending | Select-Object -First 1 |
    ForEach-Object { Select-String -Path $_.FullName -Pattern '127\.0\.0\.1|connect|refused|timeout|Send Request' | Select-Object -Last 6 | ForEach-Object { $_.Line.Trim() } }

# ④ 立刻复锁（这一步别忘）
icacls "$u" /deny "${U}:(X,WD,AD,WEA,WA,DE)"
"已复锁，复核: " + $(if ((icacls "$u" 2>&1 | Out-String) -match 'DENY') { 'DENY 在位' } else { '复锁失败，回 5.4 重做' })
```

判据：
- 日志里出现指向 `127.0.0.1` 的请求、或连接失败/超时记录 → **闸5 生效**
- 日志里出现 `Send Request` 且之后是正常的 `Server Response` → 闸5 没生效，回第 1 步核对三个值
- 完全没有任何新日志 → 更新器在别处被拦住了（闸3 之外的机制），不影响结论，但说明这条验证路径没跑通

**最后一条通用判据**：只要界面**没有**出现「发现新版本」气泡或弹窗，就没有新版本被检测到。出现了 → 三个值里有漏改，优先查 `UpdateSecSvr`。

#### 12.5.5 三种状态怎么判（与自动版界面口径一致）

自动版的状态网格里「升级通道」一行有三种颜色，手动操作时按这张表自行判断，两边口径完全相同：

| 状态 | 判定条件 | 含义 | 要不要处理 |
|---|---|---|---|
| **已禁用**（绿） | 三个值**全部**指向 `127.0.0.1:9` | 闸5 已生效 | 不用 |
| **正常**（灰） | 三个值**全部**还是 `wps.cn` 原始地址 | 闸5 没做，或已被还原 | 想做就回 12.3 |
| **未知**（黄） | 三个值里只有一部分被改，或值缺失、格式异常 | 改到一半 / 被某次升级部分重置 | 回 12.2 重新备份，再跑一次 12.3 把三个值补齐 |

自检命令：

```powershell
$K = 'HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common'
$vals = foreach ($n in 'UpdateSvr','UpdateSecSvr','NotifySvr') {
    [pscustomobject]@{ Name = $n; Value = [string](Get-ItemPropertyValue -Path $K -Name $n -ErrorAction SilentlyContinue) }
}
$vals | Format-Table -AutoSize
$blocked = @($vals | Where-Object { $_.Value -match '127\.0\.0\.1' }).Count
$official = @($vals | Where-Object { $_.Value -match 'wps\.cn' }).Count
"升级通道: " + $(if ($blocked -eq 3) { '已禁用' } elseif ($official -eq 3) { '正常' } else { '未知（部分被改，需补齐）' })
```

### 12.6 恢复升级（完全回退）

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"
$K = 'HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common'
$o = Get-Content "$B\reg\wps-update-svr-original.json" -Raw | ConvertFrom-Json

foreach ($r in $o) {
    if (-not $r.Exists) { "跳过（原本就没有这个值）: $($r.Name)"; continue }
    $kind = if ([string]::IsNullOrEmpty($r.Kind)) { 'String' } else { $r.Kind }
    Set-ItemProperty -Path $K -Name $r.Name -Value $r.Value -Type $kind
    "已恢复: {0} = {1}" -f $r.Name, (Get-ItemPropertyValue -Path $K -Name $r.Name)
}
```

**做什么**：按备份里的原值与原值类型逐条写回，整条分号串一并还原。
**预期输出**：

```text
已恢复: UpdateSvr = http://update.wps.cn/updateserver/update;http://update2.wps.cn/updateserver/update
已恢复: UpdateSecSvr = https://update.wps.cn/updateserver/update;https://update2.wps.cn/updateserver/update
已恢复: NotifySvr = http://notify.wps.cn/notifyserver/notify
```

**失败怎么办**：
- JSON 丢了 → 用方式 B 的整键备份：`reg import "%USERPROFILE%\Desktop\wps-backup\reg\common.reg"`。
- 只恢复了第一条地址 → 说明备份是残缺的，从另一台全新安装的机器上抄原值补上。

**清 hosts 与防火墙规则**

```powershell
$h = "$env:SystemRoot\System32\drivers\etc\hosts"
$bak = Get-Item "$h.wps-before" -ErrorAction SilentlyContinue
if ($bak) { Copy-Item $bak.FullName $h -Force; "hosts 已从 $($bak.Name) 还原" } else { "无 hosts 备份，手工删除含 wps.cn 的两行" }
ipconfig /flushdns
```

```cmd
netsh advfirewall firewall delete rule name="WPS Update Block"
netsh advfirewall firewall delete rule name="WPS Update Block self"
netsh advfirewall firewall delete rule name="WPS Update Block policy"
```

**做什么**：hosts 回滚到改写前的备份并刷缓存；逐条删掉三条出站阻止规则。
**预期输出**：`hosts 已从 hosts.bak-... 还原` + `已成功刷新 DNS 解析缓存。` + 三条已删除提示。
**失败怎么办**：`没有与指定标准相符的规则。` → 该规则本来就没建，跳过；hosts 用记事本手工改也完全等价。

**恢复后复核三件事**

```powershell

(Get-ItemPropertyValue -Path $K -Name 'UpdateSvr') -split ';'
try { [System.Net.Dns]::GetHostAddresses('update.wps.cn') | ForEach-Object { $_.IPAddressToString } } catch { "解析失败" }

```

**做什么**：确认地址含 `update.wps.cn` 两条、域名解析回公网、云服务状态与第 9 章回退一致。
**预期输出**：两条含 `update.wps.cn` 的地址；解析出公网 IP（非 127.0.0.1）；服务状态与 9.4 设置相符。
**失败怎么办**：解析仍是 127.0.0.1 → hosts 没还原干净，逐行检查；地址只有一条 → 回上面用 `common.reg` 覆盖。

### 12.7 注意事项

1. **三个值要一起改。** `UpdateSvr`（明文）、`UpdateSecSvr`（HTTPS）、`NotifySvr`（通知通道）分属不同用途，只改一个，另两个仍能触发对应请求；`UpdateSvr` 内部还有第二条备用地址，所以整条串必须替换成单地址而不是只换前半段。
2. **WPS 重装或大版本升级会重建这些值**，需要重做本章。与第 11.4 的体检项一起看：体检脚本发现「载荷封锁」掉到 3/4 时，通常也意味着注册表值被重置了。
3. **值名随版本可能不同。先在改之前确认值名存在**，不存在就跳过，不凭猜测创建：

```powershell
$cands = @('HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common',
           'HKCU:\SOFTWARE\Kingsoft\Office\6.0\common')
foreach ($K in $cands) {
    if (-not (Test-Path $K)) { "键不存在: $K"; continue }
    "=== $K"
    (Get-Item $K).GetValueNames() | Where-Object { $_ -match 'Svr|Url|URL|Server|update|Update' } |
        ForEach-Object { "  {0,-16} = {1}" -f $_, (Get-ItemPropertyValue -Path $K -Name $_) }
}
```

**做什么**：把 `Common` 键下所有名字里带 `Svr` / `Url` / `Server` / `update` 的值列出来，确认真实值名。
**预期输出**（本机实测形态）：

```text
=== HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common
  UpdateSvr        = http://update.wps.cn/updateserver/update;http://update2.wps.cn/updateserver/update
  UpdateSecSvr     = https://update.wps.cn/updateserver/update;https://update2.wps.cn/updateserver/update
  NotifySvr        = http://notify.wps.cn/notifyserver/notify
```

**失败怎么办**：两个候选键都不存在 → 该版本把服务器地址放在别处（例如 `...\6.0\Common\updateinfo`）。把 `-match` 的正则放宽为 `'.'` 列出全部值名，再挑出含 `http` 的项，按同一思路改。

4. **值类型必须是 `REG_SZ`（String）。** 写成 `REG_MULTI_SZ` 或多行文本，更新器按字符串读会解析失败并回落到内置地址，等于没改。
5. **改值后不需要重启。** 更新器每次检查前都重新读注册表；但若 WPS 主程序与托盘常驻，需先退出托盘图标（右键 → 退出）再重开，避免它继续用内存里的旧地址。
6. **闸5 与第 9 章回退的关系**：第 9 章「恢复原装」是文件与 ACL 层面的回退；本章的注册表值回退是独立的一步，见 12.6。两者一起做才算回到原厂状态。
