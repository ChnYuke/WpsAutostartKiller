# WPS 开机自启处置 · 快速参考卡片

> 打印版。完整原理与判据见《手动操作手册》。
> 约定：`$U` = `%USERDOMAIN%\%USERNAME%`；`$Ver` = 版本目录，如 `12.1.0.29690`

---

## 执行前必做：备份（不备份就别动手）

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName
$B    = "$env:USERPROFILE\Desktop\wps-backup"
New-Item -ItemType Directory -Force $B | Out-Null

# 1) 两条计划任务
Export-ScheduledTask "WpsUpdateTask_$env:USERNAME"      -TaskPath "\" | Set-Content "$B\WpsUpdateTask.xml"      -Encoding UTF8
Export-ScheduledTask "WpsUpdateLogonTask_$env:USERNAME" -TaskPath "\" | Set-Content "$B\WpsUpdateLogonTask.xml" -Encoding UTF8

# 2) 5 个载荷的哈希（恢复时要逐项比对）
@("$Root\ksolaunch.exe","$Ver\office6\ksolaunch.exe","$Ver\wtoolex\wpsupdate.exe",
  "$Ver\wtoolex\updateself.exe","$Ver\wtoolex\updatepolicy.exe") |
  Where-Object { Test-Path $_ } |
  ForEach-Object { "{0}  {1}" -f (Get-FileHash $_ -Algorithm SHA256).Hash, $_ } |
  Set-Content "$B\hashes-original.txt" -Encoding UTF8

# 3) 注册表与服务原配置
reg export "HKCU\SOFTWARE\Kingsoft" "$B\kingsoft.reg" /y
reg export "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" "$B\run.reg" /y
sc.exe qc wpscloudsvr > "$B\service-before.txt"

# 4) 现有 ACL
icacls "$Root" > "$B\acl-before.txt"
Get-ChildItem $B
```

**核对备份**：`hashes-original.txt` 里应有 5 行（若只有 4 行，说明该版本缺某个更新组件，属正常）。

## 五道闸（按顺序执行）

### 闸 1 · 计划任务（普通权限可禁用；删除遇 `Access is denied` 用管理员）

```cmd
schtasks /Change /TN "WpsUpdateTask_%USERNAME%" /DISABLE
schtasks /Change /TN "WpsUpdateLogonTask_%USERNAME%" /DISABLE
schtasks /Delete /TN "WpsUpdateTask_%USERNAME%" /F
schtasks /Delete /TN "WpsUpdateLogonTask_%USERNAME%" /F
```

> 报 `Access is denied` → 任务 DACL 只给了只读，此时用管理员窗口（单纯禁用通常普通权限即可）。

### 闸 2 · 服务（管理员）

```cmd
sc.exe config wpscloudsvr start= disabled
sc.exe stop wpscloudsvr
```

### 闸 3 · 文件 ACL（用户级安装普通权限即可；`Program Files` 全局安装需管理员）

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName
$U    = "$env:USERDOMAIN\$env:USERNAME"

$Exec = @("$Ver\office6\ksolaunch.exe","$Ver\wtoolex\wpsupdate.exe",
          "$Ver\wtoolex\updateself.exe","$Ver\wtoolex\updatepolicy.exe") | Where-Object { Test-Path $_ }
foreach ($f in $Exec) { icacls "$f" /deny "${U}:(X,WD,AD,WEA,WA,DE)" }
icacls "$Root" /deny "${U}:(WD,AD)"
```

**权限位含义**：`X` 执行 / `WD` 写数据 / `AD` 追加数据 / `WEA` 写扩展属性 / `WA` 写属性 / `DE` 删除

> **复核只看行为，不看显示**：`icacls` 会把上面的精确掩码打印成 `(DENY)(W,D,X)` / `(DENY)(W,D)` 这类简写 —— 这是**正确配置的正常显示形态**。验证方式是行为三条：载荷跑不起来、守卫壳写得进不去、目录建不了子项。详见手册 5.6。

> **不要用简写 `W`**。`W` 是泛型写，会连带把 `READ_CONTROL` 一起 DENY，结果是文件连读都读不了、WPS 起不来。

### 闸 4 · 守卫壳（保住图标）

WPS 主图标和计划任务共用同一个 `%LOCALAPPDATA%\Kingsoft\WPS Office\ksolaunch.exe`。
把它换成守卫壳：命中更新/自启参数就静默退出，其余转发到 `office6\wpsoffice.exe`。
完整源码、图标提取代码、编译命令见手册第 4 章。

改名顺序（**必须先解 DENY，否则重命名被拒**）：

```powershell
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$U    = "$env:USERDOMAIN\$env:USERNAME"
icacls "$Root" /remove:d "$U"
icacls "$Root\ksolaunch.exe" /remove:d "$U"
Rename-Item "$Root\ksolaunch.exe" "ksolaunch.real.exe"
Copy-Item "<守卫壳.exe>" "$Root\ksolaunch.exe"
icacls "$Root\ksolaunch.exe"    /deny "${U}:(WD,AD,WEA,WA,DE)"
icacls "$Root\ksolaunch.real.exe" /deny "${U}:(WD,AD,WEA,WA,DE)"
icacls "$Root"                  /deny "${U}:(WD,AD)"
```

### 闸 5 · 升级通道（改 3 个注册表值，普通权限即可）

```powershell
# 备份 → 改写，一条命令走完；值不存在自动跳过
$B = "$env:USERPROFILE\Desktop\wps-backup"
New-Item -ItemType Directory -Force "$B\reg" | Out-Null
$K = 'HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common'
$key = Get-Item $K
$snap = foreach ($n in 'UpdateSvr','UpdateSecSvr','NotifySvr') {
    $v = Get-ItemPropertyValue -Path $K -Name $n -ErrorAction SilentlyContinue
    if ($null -eq $v) { [pscustomobject]@{ Name=$n; Exists=$false; Kind=''; Value='' } }
    else { [pscustomobject]@{ Name=$n; Exists=$true; Kind=$key.GetValueKind($n).ToString(); Value=$v } }
}

# 防覆盖：已有干净备份就另存带时间戳，绝不拿"已经改过的值"盖掉原始备份
$out = "$B\reg\wps-update-svr-original.json"
if (Test-Path $out) {
    $old = Get-Content $out -Raw
    if ($old -match '127\.0\.0\.1') {
        "检测到已有备份被污染，用本次值修正"
    } else {
        $out = "$B\reg\wps-update-svr-original.$((Get-Date).ToString('yyyyMMdd-HHmmss')).json"
        "已有干净备份，本次另存为 $out（不覆盖原文件）"
    }
}
$snap | ConvertTo-Json -Depth 3 | Set-Content $out -Encoding UTF8
"备份写入: $out"

$map = [ordered]@{
    UpdateSvr    = 'http://127.0.0.1:9/updateserver/update'
    UpdateSecSvr = 'https://127.0.0.1:9/updateserver/update'
    NotifySvr    = 'http://127.0.0.1:9/notifyserver/notify'
}
foreach ($k in $map.Keys) {
    if ($null -eq (Get-ItemPropertyValue -Path $K -Name $k -ErrorAction SilentlyContinue)) { "SKIP $k"; continue }
    Set-ItemProperty -Path $K -Name $k -Value $map[$k] -Type String
    "$k = " + (Get-ItemPropertyValue -Path $K -Name $k)
}
```

> 为什么是 `127.0.0.1:9`：9 是 discard 端口，本机无人监听，连接**立即被 RST 重置**；指向不存在的域名会等 DNS 超时，WPS 启动会卡十几秒。回环地址不产生外网流量。

**可选加固（管理员）**

```cmd
:: hosts 追加一行（路径 %SystemRoot%\System32\drivers\etc\hosts）
echo 127.0.0.1 update.wps.cn update2.wps.cn notify.wps.cn >> "%SystemRoot%\System32\drivers\etc\hosts"
ipconfig /flushdns
:: 按程序封锁出站
netsh advfirewall firewall add rule name="WPS Update Block" dir=out program="%LOCALAPPDATA%\Kingsoft\WPS Office\12.1.0.29690\wtoolex\wpsupdate.exe" action=block enable=yes
```

**验证**：三个值都显示 `127.0.0.1:9` → 打开 WPS → 查 `HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common\updateinfo\cacheStatusInfo\wpsUpdateStatus` 应为 `UpdateError`，界面无「发现新版本」。

### 恢复升级

```powershell
$B = "$env:USERPROFILE\Desktop\wps-backup"
$K = 'HKCU:\SOFTWARE\Kingsoft\Office\6.0\Common'
$o = Get-Content "$B\reg\wps-update-svr-original.json" -Raw | ConvertFrom-Json
foreach ($r in $o) {
    if (-not $r.Exists) { "跳过 $($r.Name)"; continue }
    $kind = if ([string]::IsNullOrEmpty($r.Kind)) { 'String' } else { $r.Kind }
    Set-ItemProperty -Path $K -Name $r.Name -Value $r.Value -Type $kind
    "已恢复 $($r.Name)"
}
```

```cmd
:: 清 hosts（手工删掉含 wps.cn 的那行）+ 删防火墙规则
ipconfig /flushdns
netsh advfirewall firewall delete rule name="WPS Update Block"
```

> 三个值必须整条恢复（含分号后的第二条地址）。只恢复第一条，仍会走备用域名。

## 验收

```powershell
# A) 自启四种参数，全部应为 0 进程
$k = "$env:LOCALAPPDATA\Kingsoft\WPS Office\ksolaunch.exe"
foreach ($a in '/wpsupdate -from=task -source=task','-createtask','-repairtask','/prometheus /from=autostart_after_install') {
    Start-Process $k -ArgumentList $a; Start-Sleep 4
    "$a -> " + (Get-Process wps,wpsoffice,wpscloudsvr -EA SilentlyContinue).Count
}

# B) 正常入口应能开（依次点桌面 / 开始菜单 / 任务栏图标）
#    判据：进程数 >= 3 且存在 MainWindowTitle 为 "WPS Office" 的进程
#    进程数在 3~8 之间浮动（最小化 / 首页 / 打开文档各不同），不要卡数字
$procs = @(Get-Process wps,wpsoffice -EA SilentlyContinue)
"进程=$($procs.Count) 主窗口=" + @($procs | Where-Object { $_.MainWindowTitle -like '*WPS Office*' }).Count

# C) 看守卫壳日志
Get-Content "$env:LOCALAPPDATA\Kingsoft\wps-guard.log" -Tail 10
```

日志判读：

| 内容 | 含义 |
|---|---|
| `BLOCKED args=[/wpsupdate -from=task -source=task]` | 计划任务被拦下（正常） |
| `BLOCKED args=[/prometheus /from=autostart_after_install]` | 安装器自启被拦（正常） |
| `LAUNCH ... from=startmenu` / `from=taskbar` | 有人点了图标，正常转发 |
| `NO-TARGET` | 找不到主程序，重跑一次闸 4 |
| `FAIL ... err=` | 转发异常，把整行留作排查 |

## 恢复原装（五步，顺序不可乱）

```powershell
# ① 关进程
Get-Process wps,wpsoffice,wpscloudsvr,ksolaunch,promecefpluginhost -EA SilentlyContinue | Stop-Process -Force
Start-Sleep 4

# ② 解 DENY（先父目录，再文件）
$Root = "$env:LOCALAPPDATA\Kingsoft\WPS Office"
$Ver  = (Get-ChildItem $Root -Directory | Where-Object Name -match '^\d+(\.\d+)+$' | Sort-Object { [version]$_.Name } -Descending)[0].FullName
$U    = "$env:USERDOMAIN\$env:USERNAME"
foreach ($p in @($Root,"$env:LOCALAPPDATA\Kingsoft\WPS Cloud Files\update",
    "$Root\ksolaunch.exe","$Root\ksolaunch.real.exe","$Ver\office6\ksolaunch.exe",
    "$Ver\wtoolex\wpsupdate.exe","$Ver\wtoolex\updateself.exe","$Ver\wtoolex\updatepolicy.exe") | Where-Object { Test-Path $_ }) {
    icacls "$p" /remove:d "$U"
}

# ③ 还原启动器
Remove-Item "$Root\ksolaunch.exe" -Force
Rename-Item "$Root\ksolaunch.real.exe" "ksolaunch.exe"

# ④ 重建计划任务
Register-ScheduledTask -Xml (Get-Content "$env:USERPROFILE\Desktop\wps-backup\WpsUpdateTask.xml" -Raw)      -TaskName "WpsUpdateTask_$env:USERNAME"      -Force
Register-ScheduledTask -Xml (Get-Content "$env:USERPROFILE\Desktop\wps-backup\WpsUpdateLogonTask.xml" -Raw) -TaskName "WpsUpdateLogonTask_$env:USERNAME" -Force

# ⑤ 恢复服务 + 复核哈希
sc.exe config wpscloudsvr start= demand
"$Root\ksolaunch.exe" | ForEach-Object { (Get-FileHash $_ -Algorithm SHA256).Hash }
# 与 hashes-original.txt 里根 ksolaunch.exe 那行比对，必须一致
```

复核通过后重启一次，WPS 的全部默认行为（自动更新、重建自启任务、开机自启）回归即为原装。

## 故障速查

| 症状 | 原因 | 处置 |
|---|---|---|
| 图标变成默认程序图标 | 守卫壳编译时没带 `/win32icon` | 重编，加 `/win32icon:...`；再 `ie4uinit.exe -show` |
| 点图标毫无反应 | 拦截词误伤正常参数（如 `/prometheus`） | 必须 token 精确匹配（子串匹配是事故根源） |
| 任务栏图标不灵、开始菜单正常 | `from=task` 是 `from=taskbar` 的子串 | 同上，token 化比对 |
| WPS 自动更新没了 | 正常，自启与更新共用同一入口 | 需要时手动装新版，装完重跑四道闸 |
| 重装后自启又回来 | 安装程序重铺文件，ACL 重置 | 重跑四道闸 |
| 开机进安全模式 | 有人写过 `bcdedit safeboot` | `bcdedit /deletevalue {current} safeboot` |
| 升级照旧发生 | 只改了 `UpdateSvr`，`UpdateSecSvr` 仍是官方地址 | 三个值一起改成 `127.0.0.1:9`，整条替换 |

---

## 记住这三条

1. **`ksolaunch.real.exe` 务必保留** —— 恢复原装全靠它。
2. **`wps-backup` 目录务必保留** —— 计划任务 XML 和哈希基线在里面。
3. **WPS 重装后必须重跑** —— 否则 ACL 重置，自启复活。
